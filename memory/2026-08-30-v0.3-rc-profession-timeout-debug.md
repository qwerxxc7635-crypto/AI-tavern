# V0.3 RC 职业池 TIMEOUT 调试记录

## 根因假设

`GENERATE_CAREER_POOL` 在 DeepSeek 上使用 provider-default thinking，并被过短 Queue 整体时限截断；Queue 取消与 commit 边界未贯穿。

## 可证伪实验

- 最小 JSON + non-thinking：2.187s，`STOP`，JSON 正常。
- 职业权威 Prompt + provider default + 8s idle：8.004s `TIMEOUT`。
- 同一职业 Prompt + non-thinking：13.691s，`STOP`，1262/1421 tokens。该结果已超过生产 Queue 的 12s 总时限。
- 追踪代码确认远端 Provider 实际有 60s minimum，截图 TIMEOUT 由 12s Queue 先触发；但 signal 未传给 Provider，因此当时只结束 UI 操作，不保证终止后台请求。

## 修复与验证

- DeepSeek 严格结构任务统一 non-thinking。
- 职业池 4096 token / 60s idle / 150s operation；Queue signal 贯穿 Provider/HTTP，commit 纳入去重区。
- HTTP 时限改为首包/无进度 deadline，chunk 重置，300s 安全总上限。
- 真实三世界职业验收全部最终通过；2048 token 在第三世界以 `LENGTH` 截断并 fail closed，故依真实 3071-token 样本校准为 4096。

## 结论

根因假设被差分证实。本问题与 JSON/Schema `INVALID_OUTPUT` 分层独立；截断响应继续按 `RESPONSE_TRUNCATED` fail closed，不通过放宽 Schema 解决。
