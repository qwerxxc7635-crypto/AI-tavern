# Ember Tavern V0.3 Director Budget

Status: M8-T05 implementation contract

Global visual standard: [`EMBER_TAVERN_VISUAL_STYLE_GUIDE_V1.md`](EMBER_TAVERN_VISUAL_STYLE_GUIDE_V1.md)

## 1. Authority boundary

Director Budget is a local admission controller between an immutable World Director run and its downstream Rules/Generator/Faction Rules route. Approval reserves capacity; it does not execute a proposal or modify World Fact, Quest, NPC, Faction, Clock, Adventure, Message, or Event state. Every downstream result still passes its existing validator and SQLite transaction.

Player P0 operations are outside this channel. A `PLAYER_ACTION` may trigger a Director run, but the committed player action itself is never queued, delayed, rejected, charged, or reordered by Director Budget.

## 2. Authoritative clock and limits

The only clock is `character_rule_states.game_time_minutes`. Wall time and model output have no budget authority. A game day is `floor(game_time_minutes / 1440)`; the next admission after a day change resets daily counters in the same immediate transaction.

| Budget | Limit | Proposal mapping |
| --- | ---: | --- |
| Active Quest reservations | 4 | `OPPORTUNITY`; existing `ACTIVE` Pool rows plus approvals |
| Daily events | 4/day | `OPPORTUNITY`, `FORESHADOW`, and every urgent event |
| Urgent events | 2/day | `PRESSURE` |
| NPC proactive | 2/day | `NPC_ACTION` |
| Background changes | 3/day | `WORLD_CHANGE`, `FACTION_ACTION` |
| Maintenance | exempt | `QUEST_UPDATE`, `QUEST_EXPIRE` |

The M8-T03 open-Quest limit of 12 remains a separate hard creation safety valve. The Active Quest budget is a pacing reservation and cannot weaken that limit.

## 3. Cooldown and starvation

Cooldowns are keyed by the proposal's deterministic `cooldownKey`: opportunity, NPC, faction, and world change use 720 game minutes; foreshadow uses 360; pressure uses 180; convergent Quest maintenance has no cooldown.

Over-capacity or cooling proposals remain durable `DEFERRED` entries with a reason and `eligibleGameTime`. They are reconsidered whenever a later run is admitted. Ordering uses urgency plus up to three points of waiting-age promotion, then oldest request, stable run ID, and ordinal. A low-priority request waiting three game days therefore outranks fresh high-priority work; hard capacity, active-Quest limits, and cooldowns are never bypassed.

## 4. Persistence and observability

Schema 27 adds:

- `director_budget_states`: persisted day, authoritative game time, usage, revision, and update time;
- `director_budget_admissions`: one idempotency marker per Director run, including empty runs;
- `director_budget_entries`: approved/deferred proposal queue with category, reason, and eligibility;
- `director_budget_cooldowns`: latest next-eligible game time per Campaign/key;
- `director_budget_decisions`: append-only evaluation history.

Admission uses `BEGIN IMMEDIATE`. It validates run ownership, records the run once, rolls usage forward from the Rules clock, considers all pending work deterministically, stores every decision, then commits the state. Approval consumes capacity at reservation time so downstream retry cannot amplify content. Replaying the same run is read-only and returns the stored snapshot.

Internal snapshots include all five schema-27 tables in foreign-key order and treat them as empty for older payloads. Reopening the SQLite save preserves usage, queue, cooldown, revision, and day. Portable `.emtavern` remains format v2; formal schema-27 portable migration belongs to M10-T05.

## 5. Desktop integration and scope

TypeScript Persistence and Rust Native implement the same categories, limits, cooldowns, day rollover, priority aging, and idempotency rules. Tauri exposes admit/read commands. Windows `DirectorBudgetService` first commits the existing deterministic Director run, then admits it; it has no timer, Provider, or background model loop.

M8-T05 adds no page or CSS. Any future budget/history projection must reuse the existing Design Tokens, UI Primitives, and Game Components under the visual guide. Feature/Legacy migration and final Visual Consistency Audit remain M10-T07. M9 is not part of this task.
