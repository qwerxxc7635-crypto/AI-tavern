# Ember Tavern V0.3 Dynamic Career Pool

全局视觉规范：`docs/EMBER_TAVERN_VISUAL_STYLE_GUIDE_V1.md`

## 1. 目标与边界

M6-T01 以世界级 `CareerPool` 取代玩家可见的固定四职业列表。职业是符合锁定 World Constitution 的叙事实体，不是属性、金钱、装备或检定修正的规则入口；AI 只提出结构化候选，本地合同、Domain 和 Native 事务决定其能否成为 SQLite 事实。

固定 `WARRIOR / ROGUE / SCHOLAR / DIPLOMAT` 只保留为 V0.2 `legacyArchetype` 兼容投影，不再作为角色创建页的核心选择。

## 2. 合同与世界约束

version 1 `CareerDefinition` 包含：

- 世界内唯一 `id` 和按全角 ASCII、空白及大小写规范化后唯一的 `name`；
- `COMMON / UNCOMMON / RARE / SPECIAL` rarity；
- `role`、`skills`、`equipmentTags`、`socialPosition`、`relationshipHooks`、`risks` 和 `requirements`；
- 与锁定 Constitution 精确一致的 `careerRules / society / technology / economy` 证据；
- `INITIAL_GENERATION / RUNTIME_DISCOVERY / LEGACY_MAPPING` 来源、generation provenance 和显式 V0.2 原型映射。

初始池必须精确生成常见、少见、稀有、特殊各一项。运行时发现可按请求 rarity 追加，但必须继续绑定原 Campaign 和 Constitution revision，且不能与既有 ID 或规范化名称重复。三个不同世界通过同一合同生成不同职业内容，不把世界类型硬编码到核心 schema。

职业合同不包含 numeric bonus。职业对属性、财富、装备、Trait 或 D20 的影响必须经对应后续 Rules 合同实现，不能从职业描述反解析数值。

## 3. 生成、队列与提交

统一任务 `GENERATE_CAREER_POOL` 使用既有 Provider、Generator Runner、结构修复、Context Budget 和审计栈。Windows 服务将职业池生成提交到既有 Generation Queue 的 P2 优先级；相同 Campaign、模式、Constitution revision、池 revision 和 rarity 意图去重。队列取消或超时后会在 Native 提交前再次检查取消信号，迟到输出不能写入事实。

Native `career_pool_generation_commit` 在单一 immediate transaction 内复核：

1. Campaign、锁定 Constitution、请求上下文和 expected pool revision；
2. requested count/rarity 与输出精确一致；
3. 所有结构字段、Constitution 证据、ID、名称及既有池去重；
4. generation audit 的 task、raw/validated 一致性和幂等键；
5. generation record 与 Career Pool 同事务写入。

失败不留下 generation record、部分职业或池 revision。相同已提交幂等键重放返回既有池，不重复追加。

## 4. SQLite 与角色集成

schema 15 新增每 Campaign 唯一的 `career_pools`。表列与 canonical JSON 互相校验，身份、schema、Constitution revision 和创建时间不可变；更新必须严格 revision +1。存在 Campaign 时禁止删除职业池。

TypeScript Repository 与 Rust Native 在每次读取时重新对照锁定 Constitution 的 revision 和四项证据，不能只信任持久 JSON。Universal Character 的非空 Career ID 必须引用同 Campaign 池中的精确 ID、显示名和 legacy mapping；角色创建启动、Quick 输出、Advanced 保存及最终确认均在相应边界复核该引用。

旧 V0.2 角色的 `career.id = null` 仍可读取；动态职业通过显式 `legacyArchetype` 和当前显示名投影到 V0.2 合同。完整 portable `.emtavern` 格式升级及历史存档携带职业池仍属于 M10-T05，本任务只证明本地 SQLite 关闭重开。

## 5. UI 与后续边界

角色创建页从持久 Career Pool 渲染职业名称、rarity、职责、社会位置、要求和风险；池缺失时触发初始生成并提供失败重试。页面不再提供固定四原型或自由文本职业入口。

本次自然修改的 UI 复用现有 Design Token、角色布局和 Game Component，并以世界/命运生成表达 AI 身份。没有提前执行 M10-T07 Legacy UI Migration，也没有为职业建立第二套组件或样式体系。

M6-T01 不实现装备、NPC LOD、地点、势力或 portable archive 升级，不修改 Rules Engine、D20、Quest、Adventure、AI Provider 或存档状态机的既有业务语义。
