# Ember Tavern V0.3 Cache Optimization

## 1. 边界与证据

M10-T04 优化的是 Provider 请求中由应用控制的稳定前缀布局，不建立第二份游戏状态缓存，也不改变 Rules Engine、SQLite、Quest、NPC、Adventure 或存档合同。

缓存证据分为两个互不替代的来源：

- **Provider observation**：仅当 DeepSeek 响应 usage 同时明确返回 `prompt_cache_hit_tokens` 和 `prompt_cache_miss_tokens` 时记录。hit、miss 和 ratio 是 Provider 用量证据。
- **Session prefix observation**：当前进程只观察同一个稳定前缀 SHA-256 是否曾出现，结果为 `PREFIX_FIRST_SEEN` 或 `PREFIX_REUSED`。它不证明 Provider 命中，也不用于计费。

Provider 未返回缓存字段时保持 `UNKNOWN/null`，禁止由重复哈希、延迟或输入 token 反推命中。

## 2. Stable Prefix + Dynamic Tail

应用控制的稳定前缀按以下顺序生成：

1. `SYSTEM_CONTRACT`
2. `GAME_RULES`
3. `OUTPUT_SCHEMA`
4. `PROMPT_PROFILE`
5. `STABLE_WORLD_TRUTHS`
6. `USER_GUIDANCE`

Stable Prompt Profile 已推进为 `deepseek-v4-flash-prefix-v4`。`STABLE_WORLD_TRUTHS` 只投影 Unified Context 中 `stability=stable` 且 `type=rules` 的已授权 block，即 World Constitution / locked world rules；每项包含 `sourceRevision`、block `version` 和规则内容。随机 block/source ID 不进入字节，revision 或规则内容变化必须使前缀变化。

投影会排除 UUID、request ID、created/updated/locked/recorded 时间、transient error、cache metric 与 UI debug 元数据。这些字段和完整原任务输入仍在动态尾部，因此缓存布局不会删减模型完成任务所需的正确上下文。

Recent History、Scene/State、Actor Knowledge、Memory 和 Player Action 不进入稳定规则投影。玩家行动改变时，稳定前缀保持逐字节一致；Prompt Profile、用户 Prompt Manager revision、Constitution revision 或稳定规则改变时，前缀必须失效。

`cachePrefixHash` 是应用实际发送的稳定 Profile UTF-8 内容 SHA-256，不包含 Prompt、玩家输入、request ID、credential 或隐藏知识。Provider 自身在线路层加入的角色封装不由应用伪装为可验证字节。

## 3. 指标与保留

真实 DeepSeek Provider 指标继续使用 device-local `app_settings.deepseek_cache_metrics_v1`，每项只有 task、hit、miss、ratio、prefix hash 和 recorded time，原子保留最近 200 项。它不是 Campaign 事实，不进入 portable 存档。

会话前缀观察使用进程内 200 项 LRU，只保留 64 位哈希。AI Inspector 分别展示 Provider observation 与 session observation，并同时展示 Provider 明确上报的 prompt/output/cache tokens 和端到端 latency。失败或未知用量不写成 0。

M10-T04 同步补齐新 AITask 的指标白名单，并修复 Rust 指标 JSON 往返后以浮点严格相等验证 ratio 的误拒绝；现在仅允许 `f64::EPSILON` 内的序列化误差，hit/miss 整数仍须精确合法。

## 4. 基线对比

在 2026-08-24 使用 M1-T04 相同 Fake Provider schema、每任务 10 个样本重跑。该证据只比较本地调度开销，不证明真实网络、token 或缓存表现。

| Task | M1 P50/P95 ms | M10-T04 P50/P95 ms | Cache/token evidence |
| --- | ---: | ---: | --- |
| World | 0.068 / 1.857 | 0.120 / 2.294 | unknown |
| NPC | 0.203 / 2.003 | 0.204 / 1.845 | unknown |
| Quest | 0.060 / 0.645 | 0.061 / 0.601 | unknown |
| Action | 0.073 / 1.128 | 0.096 / 1.237 | unknown |
| D20 | 0.081 / 0.234 | 0.032 / 0.241 | unknown |

两轮均保留一个受控 Quest failure 和一次 Action retry。毫秒级差异受单机调度噪声影响，不能宣称性能改善或回归；正式自动回归门仍由 M10-T06 完成。

## 5. 真实 Provider opt-in

真实 DeepSeek 验证保持显式忽略，只有调用者主动提供环境变量时运行：

```bash
EMBER_TAVERN_DEEPSEEK_API_KEY='...' \
  cargo test -p ember-tavern-windows real_deepseek_runtime_verifies_selection_cache_and_reopen \
  -- --ignored
```

测试连续发送稳定 system prefix、不同动态输入，要求两条持久指标使用同一 prefix hash、第二次 Provider hit token 大于 0，并验证关闭重开后的指标和模型选择。测试不打印或持久化 API Key、Prompt 或玩家输入。常规门禁不读取凭据，也不运行该测试。

## 6. 验收映射

- byte stability：canonical JSON、稳定规则投影及桌面请求集成测试。
- revision invalidation：Prompt/Profile 与 Constitution source revision 测试。
- privacy：随机身份、UUID、时间、private knowledge 和动态行动均不进入稳定投影或指标。
- metric cap：TypeScript/Rust Provider 指标 200 项上限与 session LRU 200 项上限。
- real Provider：显式 opt-in ignored test；默认门禁保持 `NOT_RUN`。
