# Ember Tavern V0.3 Active Factions

## 1. 范围与权威边界

M6-T05 把 World Bible 中已经确认的 Faction 身份投影为可渐进激活、可行动并可恢复的本地实体。SQLite 是 Goal、Resource、Leadership、Enemy、Ally、Territory、Current Action、Player Relation 与行动历史的唯一真实来源。

`GENERATE_FACTIONS` 只把明确请求的既有 OUTLINE 补全为 ACTIVE 候选：不得创建新 Faction、改名、改 Goal、删除既有 Territory/关系，或直接执行行动。Domain 与 Native 均重新核对锁定 Constitution 证据、引用白名单和关系对称性后才提交 generation audit 与档案。

## 2. 数据模型

schema 18 新增：

- `active_factions`：保存 canonical version 1 profile、Constitution revision、OUTLINE/ACTIVE、generation provenance 与严格递增 revision。
- `faction_action_events`：保存 append-only 行动、调用来源、本地重算 cost、预算决定、proposal、受影响 Faction 前后快照、可选 Quest 迁移与 World Fact。

Constitution 锁定时，已有 World Bible Faction 自动投影为 OUTLINE；初始 Territory 直接从同一 World Bible 的 Location 所属关系计算，避免依赖多个锁定触发器的执行顺序。OUTLINE 不伪造资源、领导或当前行动。

## 3. 激活规则

- 每次显式激活 1–16 个既有 Faction，输出 ID 集必须与请求完全一致。
- name、goal、player relation 和四项 Constitution evidence 必须逐字延续。
- resources、leadership 和 current action 在 ACTIVE 中必须非空；列表规范化去重。
- Enemy 与 Ally 不得包含自己、不得重叠，且激活批次内必须双向一致。
- 既有 Enemy、Ally 与 Territory 只能延续，不能由生成候选静默删除；Location/Faction 引用必须来自本地白名单。
- 相同 generation 只允许完全一致的幂等重放；冲突输出 fail closed。

## 4. 行动、预算与后果

行动类型闭集为 `MOBILIZE`、`EXPAND_TERRITORY`、`DIPLOMACY`、`SUPPORT_QUEST`、`UNDERMINE_QUEST`、`RECOVER`。来源闭集为 PLAYER、WORLD_EVENT、DIRECTOR。

每个 proposal 必须声明所需资源、明确目标与 1–8 个结构化 consequence。本地固定成本为：Resource/Player Relation 1 点，Territory/Relation/World Fact 2 点，Quest 3 点；单次最多 6 点、一个 Quest 变化和一个 World Fact。调用者预算只能把这些上限收紧，不能放宽。M8 World Director 可复用该 envelope，但 M6-T05 不提前实现每日预算恢复、调度器或冷却。

后果只允许：

- 增删 Actor 的 Resource 或 Territory；
- 双向原子更新 Ally/Enemy/Neutral；
- 更新 Player Relation；
- 经既有 Quest 状态机执行一个合法迁移；
- 创建一个带 Actor Faction 归属的 Developing Fact。

Native 在 `BEGIN IMMEDIATE` 内从当前 SQLite 重算资源拥有、引用、目标语义、Quest 迁移、成本和预算，再原子更新所有受影响实体并追加事件。AI 输出和未来 Director proposal 都不能绕过该事务。

## 5. 世界事件接口与后续边界

Faction action 以 `source=WORLD_EVENT` 或 `source=DIRECTOR` 接受外部已预算 proposal，并可产生一个 World Fact；这就是 M6-T05 的世界事件接口。它不预写势力剧情、不自动选择每日行动，也不实现 M8-T04/T05 World Director 的调度、持久预算和 cooldown。

portable `.emtavern` 仍为 format v2；schema 18 新表的正式跨版本导入导出与历史 fixture 升级属于 M10-T05。本任务不修改 Rules Engine、D20 硬结果、Provider、Quest/NPC/Adventure 核心合同、World Seed 或存档状态机。

## 6. UI 与视觉规范

M6-T05 提供桌面服务和 Tauri 命令，不新增 Faction 页面，也不返工既有页面。后续自然展示势力时复用现有 Design Token、UI Primitive 与 Game Component，并遵循 [`EMBER_TAVERN_VISUAL_STYLE_GUIDE_V1.md`](EMBER_TAVERN_VISUAL_STYLE_GUIDE_V1.md)。Feature Page、Legacy UI Migration 和最终 Visual Consistency Audit 仍由 M10-T07 统一收敛，视觉调整不得改变本文件中的业务语义与状态机。

## 7. 验证矩阵

- 合同：八项字段、OUTLINE/ACTIVE 约束、重复/非法引用。
- 激活：ally/enemy 对称、身份与 Territory 延续、Constitution 证据、幂等。
- 行动：resource、territory、双向关系、player relation、合法/非法目标和预算。
- 后果：Quest 状态迁移、World Fact 限额与本地重算。
- 持久化：revision 竞争、append-only history、事务回滚、关闭并重开 SQLite。
- 桌面：相同激活意图合并；本地行动不调用生成器。
