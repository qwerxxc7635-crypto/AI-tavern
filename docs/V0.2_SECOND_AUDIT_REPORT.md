## 真人测试反馈复核

### SA-USER-001 新建存档应直接进入世界构筑 — VERIFIED

`SaveHomePage.createCampaign()` 创建成功后直接导航到 `/world?campaignId=...`，并已有回归测试 `creates a campaign and enters world construction immediately`。

### SA-USER-002 存档选择页无法滚动 — HARDENED

基线已经把 `.save-home` 设置为独立 `overflow-y: auto` 滚动容器，但真人测试说明原生 WebView/窗口尺寸组合仍出现过不可滚动。第二轮新增 `scroll-hardening.css`，使用 `100dvh`、显式 `overflow-y: scroll`、稳定 scrollbar gutter 和 WebKit 惯性滚动，并在 `main.tsx` 中最后加载以覆盖基础样式。

### SA-USER-003 无法配置 API / PROBE_STALE — VERIFIED IN CURRENT BASELINE

当前基线在 Native probe 生成能力数据与 fingerprint 前，将 `checkedAt` 固定为前端 `Date.toISOString()` 同样的三位毫秒 UTC 格式，避免微秒时间戳进入前端后被截断并导致 probe fingerprint / receipt 校验失配；模型设置测试继续覆盖微秒 RFC3339 输入的防御性规范化。Native probe receipt 仍绑定 Provider、规范化端点、模型、能力内容与 probe fingerprint。

本轮未重新使用真实 API Key；因此这里是代码与回归测试级复核，不冒充新的真实供应商联网实测。

### SA-USER-004 NPC / 特质 / 装备应增加且由 AI 生成 — VERIFIED IN CURRENT BASELINE

当前 AI schema/prompt 已明确：

- 角色特质：AI 一次生成 8 个候选特质；
- 初始装备：AI 生成 3–6 件角色相关叙事装备，程序只保留机械规则权威；
- 酒馆 NPC：AI 生成 5 名非老板 NPC（加老板共 6 名角色），并生成 5 条来源绑定的 rumor；
- NPC 身份、外貌、人格、目标、秘密、说话方式和当前情绪均来自 AI 输出；
- schema 对数量、resident/visitor 结构、重复姓名/原型和 rumor 来源关系做硬校验。

因此真人反馈中“不要手填 NPC/特质/装备内容，应交给 AI”这一方向在当前基线已经落入生产生成链路。玩家仍保留对两个 AI 特质候选的选择权，这属于选择生成结果，不是手工编写特质。
