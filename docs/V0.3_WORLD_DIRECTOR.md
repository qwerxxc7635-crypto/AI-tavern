# Ember Tavern V0.3 World Director

Status: M8-T04 implementation contract

Global visual standard: [`EMBER_TAVERN_VISUAL_STYLE_GUIDE_V1.md`](EMBER_TAVERN_VISUAL_STYLE_GUIDE_V1.md)

## 1. Authority boundary

World Director is a deterministic local scheduler, not an AI Agent and not a second game-state authority. It reads a bounded SQLite projection, evaluates pacing, and emits ordered, explainable proposals. A proposal states when, who, and what kind of change may be useful; it never performs the change.

- `RULES` validates Quest expiry/update transitions.
- `FACTION_RULES` validates Faction actions and every consequence.
- `GENERATOR` may create narrative/content candidates only; its output must pass the existing schema, Constitution, knowledge, repetition, budget, and business-rule checks before any later commit.

Director runs do not insert or update World Facts, Quest state, clocks, factions, NPC state, messages, adventures, or game events. SQLite remains the sole truth source. No fixed main plot, privileged quest, or model-authored rule is introduced.

## 2. Deterministic input and pacing

Preparation requires an active `TAVERN`, `ADVENTURE`, or `SETTLEMENT` Campaign, its locked World Constitution revision, current location, complete Quest Pool projection, clocks, active-faction public action projection, and the most recent 20 Quest transitions and game events. Quest expiry uses the database-counted total of committed `WORLD_CLOCK_ADVANCED` events after each Quest's creation, so unrelated event volume cannot hide expiry.

Signals are sorted by stable entity ID and include open/active/blocked Quest counts, stale Quest IDs, urgent and foreshadow clock IDs, hostile Faction IDs, recent failure count, and recent event count.

```text
pressure = active quests × 2
         + blocked quests × 2
         + clocks with <= 1 step remaining × 3
         + active hostile factions with a current action
         + recent FAILED/EXPIRED transitions × 2
```

The score is capped at 99. `0–2` is `QUIET`, `3–6` is `BALANCED`, `7–10` is `PRESSURED`, and `11+` is `OVERLOADED`.

## 3. Proposal rules

- `DISCOVERED`/`AVAILABLE` Quests become expiry candidates after three committed world-clock advances; `BLOCKED` uses five. The proposal is `QUEST_EXPIRE`, high urgency, routed to Rules. Director does not change the status.
- A clock with one or zero steps remaining proposes high-urgency `PRESSURE`; exactly two steps proposes medium `FORESHADOW`.
- An active hostile Faction with a committed current action proposes `FACTION_ACTION` through Faction Rules.
- A pressured world with a blocked Quest proposes deterministic `QUEST_UPDATE` reevaluation through Rules.
- A quiet world with no open Quest proposes one local `OPPORTUNITY`; with an open Quest it proposes one low-urgency reminder for the oldest updated Quest.
- Under `OVERLOADED`, content-producing pressure, foreshadowing, and Faction proposals are suppressed. Only convergent `QUEST_EXPIRE` proposals remain.

Ordering is urgency, action-kind convergence priority, then stable target identity. One run stores at most eight proposals; overflow is retained as an `ACTION_LIMIT` suppression record. This is a bounded decision payload safety limit, not the persistent daily budget or cooldown policy owned by M8-T05.

## 4. Scheduling and commit protocol

Windows schedules only an explicit `MANUAL`, `WORLD_EVENT`, `PLAYER_ACTION`, `QUEST_TRANSITION`, or `SETTLEMENT` trigger. Equal in-flight Campaign/trigger pairs are coalesced. The service has no `AIProvider`, generation loop, timer, or automatic background-model call.

Preparation returns a canonical SHA-256 `contextDigest`. Commit starts `BEGIN IMMEDIATE`, re-prepares the current projection, rejects stale context, then atomically appends the run and its ordered proposals. `(campaign, trigger kind, trigger ID)` is unique and exact replay is idempotent; reuse with another run identity, digest, or timestamp fails closed. History is a read-only explainability surface containing signals, score, pace, rationale, effects, route, cooldown key, suppressions, and the source snapshot.

## 5. Persistence and recovery

Schema 26 adds:

- `world_director_runs`: append-only trigger identity, context digest, pacing decision, signals, suppressions, and source snapshot.
- `world_director_proposals`: append-only, rank-ordered proposal details with route and future cooldown key.

Trigger references must belong to the same Campaign and match their durable event/transition type. Internal snapshots capture and restore both tables in foreign-key order; pre-schema-26 snapshots treat them as empty. Portable `.emtavern` format v2 is unchanged; formal schema-26 portable migration remains M10-T05.

## 6. Scope and visual policy

M8-T04 adds no page and no CSS. If a later feature exposes Director history, it must reuse existing Design Tokens, UI Primitives, and Game Components under the visual guide. Feature/Legacy migration and final Visual Consistency Audit remain M10-T07. M8-T05 alone owns persistent daily budgets, cooldown enforcement, day rollover, starvation handling, and save/reload restoration of those controls.
