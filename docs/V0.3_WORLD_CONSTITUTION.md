# V0.3 World Constitution

## 目标

World Constitution 是世界生成及后续实体生成必须遵守的结构化规则，不是 Prompt 中的一段提示词。它与 World Bible 同批生成、同一事务保存，并在玩家确认世界时锁定。

核心路径：

1. `GENERATE_WORLD` / `REFINE_WORLD` v2 返回 World Bible 草稿和 version 1 Constitution。
2. AI 输出先经过严格 Schema，再经过本地 Constitution/World 一致性规则。
3. 通过的 World Bible 与 Constitution 在同一个 SQLite 事务提交；失败时两者都不落库。
4. REVIEWING_WORLD 阶段允许整体修订，每次成功提交使 Constitution revision 增加。
5. 玩家确认后，指定 revision 由 `DRAFT` 变为 `LOCKED`；数据库 trigger 阻止其后任何更新。
6. 后续生成内容必须携带 `campaignId` 与 `constitutionRevision`，通过 Domain binding validator 后才可继续进入业务规则和持久化。

## 合同

version 1 必需字段：

- 世界类型、时代、技术、魔法/力量；
- 族群、社会、政治、经济；
- 战斗规模与死亡规则；
- 职业、装备、NPC、Trait 生成规则；
- 世界禁忌。

持久元数据包含 `campaignId`、`schemaVersion`、`revision`、`status`、创建/更新时间及锁定时间。未知字段与未知版本由结构边界拒绝，空文本、过长文本和超大列表由 Schema、Repository及原生命令边界共同拒绝。

## 一致性与下游约束

当前 World 生成切片执行三项可确定的本地检查：

- `technologyLevel` 必须等于 Constitution 的 `technology`；
- `powerRules` 必须包含 Constitution 的 `magic`；
- Constitution 的每一项 `taboos` 必须存在于 World 的 `forbiddenElements`。

这些检查是最小、明确且可测试的关系，不尝试用字符串推理替代未来 Rules Engine。结构有效但关系冲突的 AI 结果会以 `WORLD_VALIDATION_FAILED` 拒绝，GenerationRecord保留安全错误证据，World和Constitution均不写入。

下游入口 `assertConstitutionBinding` 要求 Constitution 已锁定，且 campaign与revision完全匹配；它不负责生成内容本身的职业、装备、NPC或Trait业务平衡，这些规则在各自任务实现。

## SQLite 与锁定

`world_constitutions` 是独立结构化表，Campaign为外键。修订使用单行递增revision；确认使用expected revision条件更新，防止并发确认旧版本。`world_constitutions_locked_immutable` trigger在数据库层阻止已锁定记录的全部更新，因此绕过Repository也不能改写。

TypeScript和Rust Windows纵向切片都读写同一表、执行相同字段上限及一致性规则。数据库关闭后重开会恢复完整内容、revision和状态。

## 边界

- 本任务不生成完整世界图谱，也不提前生成职业、物品、NPC或任务。
- 不增加第二次模型调用；Constitution与World共享既有Generator/Provider链路。
- 不允许AI直接锁定或修改事实，锁定只能由确认命令执行。
- portable archive格式的集中升级属于`M10-T05`；本任务验收的save/reload指SQLite持久化与重开，不提前修改跨版本存档协议。
