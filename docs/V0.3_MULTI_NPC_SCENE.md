# Ember Tavern V0.3 Multi-NPC Scene

## 1. 边界与事实源

M7-T02 消费 M7-T01 的 Tavern Population 快照建立 2–6 人场景。参与者必须是在场且至少 LOD1 的稳定 NPC 身份；选择 LOD0 时先通过既有单身份 LOD promotion 聚焦。Scene、Participant、Turn 与 Proposal 均持久化在本地 SQLite schema 20，React 列表和模型输出都不是事实源。

本切片不改变 Rules Engine、D20、Quest、Adventure、NPC Dialogue、Provider、Generation Queue、World Seed/Constitution 或存档状态机，也不实现 M7-T03 的正式回复锁定、技术 Retry 与时间线冲突修复。

## 2. 单 Actor Context

`PROPOSE_TAVERN_SCENE_ACTION` 每次只扮演一个 NPC。输入只包含：

- 当前 Actor 的 LOD profile、目标、授权 Knowledge 和自己的 Memory；
- 其他参与者的可见 ID、名字、人口角色和场景状态；
- 最近公开 Turn、玩家意图、被点名 NPC 与本地允许的 Action。

其他 Actor 的目标、人格、秘密、Memory 与 Knowledge 不进入该输入。每个 Actor 独立调用同一桌面 AI 编排栈；输出中的 `citedKnowledgeIds` 必须是其输入白名单子集。Native 在提交时从当前 SQLite 状态重建每个输入并逐份比对 generation audit，禁止把多个 NPC 合成全知 Agent。

## 3. 提案与本地仲裁

Action 闭集为 `SPEAK`、`INTERRUPT`、`SILENCE`、`EAVESDROP`、`LEAVE` 和 `INTERVENE`。前三种发言行为中实际发言的是 `SPEAK`、`INTERRUPT`、`INTERVENE`，必须提供 utterance；其余行为不得提供 utterance。`INTERVENE` 只允许旁听者，`INTERRUPT` 要求已有前序场景 Turn。

本地仲裁最多选择一个发言提案，同时保留所有沉默、偷听和离开结果。排序使用被玩家点名、授权知识引用、有限 urgency 和 Action 语义；稳定 Actor ID 只作最终平局键，不按参与者顺序轮询。`LEAVE` 原子更新参与者为不可逆 `LEFT`。

## 4. 事务、并发与恢复

schema 20 包含 `tavern_scenes`、`tavern_scene_participants`、append-only `tavern_scene_turns` 和 `tavern_scene_actor_proposals`。一次 Turn 在 `BEGIN IMMEDIATE` 中写入每个 generation record、Actor proposal、仲裁结果、离开状态与 scene revision。`operation_id` 支持完全一致的幂等重放，竞争 revision、Actor 缺失、越权引用、Context 漂移或 raw/validated output 不一致均 fail closed。

Windows 服务合并同一 Scene 的并发 send，并以独立 Actor 输入并发生成候选；Native revision 是最终仲裁者。关闭并重开 SQLite 后参与者、状态、Turn 顺序、提案来源和选中结果可恢复。portable `.emtavern` schema 20 导入导出仍由 M10-T05 统一升级。

## 5. UI 与视觉规范

Tavern 页面复用 `NpcCard` 选择人口成员，复用 `DialogueView` 显示玩家、发言与被选中的非发言动作，复用 `ActionComposer` 提交场景意图。新增样式只使用现有 Design Token，不建立平行 Primitive 或 Game Component，不提前执行 Legacy UI 全面迁移；最终一致性仍由 M10-T07 收敛。

## 6. 验收

- speaker selection 由点名、知识、目标提案和本地规则决定，不固定 round-robin；
- silence、eavesdrop、leave、interruption、intervention 均有结构合同与状态校验；
- 每个 Actor 输入与知识引用严格隔离；
- 同 Scene 并发 send 不重复提交，过期 revision 拒绝；
- Scene/Participant/Turn/Proposal 和 generation provenance 可关闭重开恢复；
- UI 复用现有游戏组件并遵循全局视觉手册。
