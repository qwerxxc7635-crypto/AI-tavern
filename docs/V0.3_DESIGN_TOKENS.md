# Ember Tavern V0.3 Design Tokens

## 1. 合同

Windows桌面端以`windows-app/src/design-tokens.css`作为正式视觉值源，采用三层结构：

1. Primitive：`--et-*`原始值，只描述颜色、字体、间距、圆角、阴影、时长、缓动和层级，不携带业务含义。
2. Semantic：`--color-*`、`--font-*`、`--space-*`、`--radius-*`、`--shadow-*`、`--duration-*`和`--layer-*`按用途引用Primitive；主题只覆盖这一层。
3. Component：应用壳、导航、卡片、控件和布局面板token只引用Semantic，不直接引用原始颜色。

新组件不得在TSX中写视觉值，不得在组件层新增hex/rgb颜色。尚未迁移页面可暂时使用`--ink`、`--muted`、`--panel`等兼容别名，但别名本身必须指向Semantic token。

## 2. 主题与无障碍

默认主题是深色Ember主题；NPC对话、任务板和冒险页面在自身根节点覆盖Semantic token为浅色Paper主题。主题作用域只改变含义映射，不复制组件规则，也不改变游戏状态。

WCAG 2.2适用合同如下：

- 两个主题的主文本对背景至少7:1。
- 正文尺寸的次级、强调和正向文本对背景至少4.5:1。
- 焦点环对相邻背景至少3:1；键盘焦点继续使用`:focus-visible`。
- 系统请求`prefers-reduced-motion: reduce`时，Semantic交互时长降为1ms，导航、加载和D20已有动画显式禁用；这不会跳过游戏规则或缩短业务超时。

层级固定为content 0、navigation 10、sticky 20、overlay 100、modal 200、toast 300。页面不得以任意大`z-index`争夺层级。

## 3. 本任务迁移范围

M2-T01只迁移应用body、sidebar、navigation、titlebar、My核心卡片，以及NPC对话、任务板和冒险的页面背景/主面板。`theme.css`中的原始颜色出现次数从任务开始时的92处降到43处，减少49处（约53%）。其余旧页面保持行为和布局不变，后续按页面渐进迁移。

本任务补齐此前被使用但未定义的display/body字体、muted文本和Ember强调别名。没有引入CSS框架、主题状态库或运行时JavaScript。

## 4. 后续迁移规则

1. 先在Primitive中复用现有值；只有确有新视觉语义时才新增Primitive。
2. 页面与组件只选择Semantic/Component token；不得为了通过检查把单次任意值包装成无意义token。
3. 每次迁移一个可验收页面或组件族，删除其不再使用的兼容别名，并保持四分辨率证据。
4. M2-T02的Primitives使用现有control/card/focus/motion/layer合同；M2-T03的Game Components在其上增加组件token，不反向覆盖Primitive。
5. 主题新增或调色必须同时更新自动对比度测试和视觉证据；不能降低阈值来接受不可读配色。

## 5. 验证视口

桌面smoke固定为860×600、1180×760、1366×768和1920×1080。860宽度仍使用完整15.5rem sidebar并为workspace保留612px；760px以下切换为5.2rem紧凑sidebar。每个视口都必须检查无横向页面溢出、焦点可见、主操作可达及Paper/Ember主题没有变量回退。

本次本地浏览器证据在四个视口分别得到workspace宽度612、932、1118和1672px；所有视口的document/body scroll width等于viewport width，未出现页面级横向溢出。860×600与其余三个视口均正确解析深色canvas `#101821`、主文本 `#e8edf0`、焦点色 `#92a67a`和navigation layer 10，控制台没有CSS或渲染警告。
