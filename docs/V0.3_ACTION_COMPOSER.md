# Ember Tavern V0.3 Action Composer

## 1. 单一输入合同

NPC对话和冒险/调查使用同一个`ActionComposer`。组件始终渲染自由Textarea；3–5个候选只是把文字填入同一草稿，玩家可以继续编辑或完全忽略。提交时，纯状态机把两条来源统一为`ActionSubmission { id, text, origin, suggestionId }`；下游合法性、Application use case与持久化入口只读取同一个`text`，候选不获得额外规则权限。

Action Composer支持鼠标、原生表单提交和`Ctrl/⌘ + Enter`。候选使用`aria-pressed`与非颜色结构标记；输入具有label、description、4000字符上限、disabled/loading和live status。NPC和冒险页面不再分别维护候选按钮与Textarea结构。

## 2. 状态与并发

`action-composer-state.ts`定义`EDITING`、`SUBMITTING`、`STREAMING`、`ERROR`、`RECOVERING`和`DISABLED`。活动提交期间拒绝编辑、选择、二次提交和禁用切换；所有stream、commit、fail、cancel与恢复事件必须匹配submission ID，迟到事件不改变状态。

失败保留原草稿和完整上次提交；retry只替换技术submission ID，复用同一文字及来源。cancel清除流式临时输出但保留草稿。`RESTORE_PENDING`恢复SQLite中已提交的工作为RECOVERING，不再次提交；恢复完成后才清空草稿。NPC另有in-flight ref，双击不能穿过React渲染时序重复发送；冒险继续使用原有in-flight ref、幂等服务和SQLite恢复帧。

组件可投影stream chunk、取消、错误和重试。当前NPC/冒险服务返回终态响应，因此页面不伪造stream或假取消；实际Provider streaming由M10-T03接入同一合同，生成队列取消由M3-T02提供。

## 3. 候选与场景

新生成的NPC话题和活动冒险行动均要求3–5个非空、唯一候选。NPC Reply schema/prompt升级为v4，Fake Provider同步输出3项；冒险此前已有3–5约束。结束场景和没有可用建议时允许0项，仍永久显示自由输入。加载旧存档时允许显示历史1–2项建议，避免把新生成约束错误用作存档迁移门禁。

- NPC：建议话题或自由文本最终调用同一`service.send`。
- 冒险行动/对话：候选或自由文本最终调用同一`service.act`。
- 调查：当前纵向切片由冒险`OBSERVE`意图承载，与ACTION/DIALOGUE共享Composer、合法性和持久化路径；没有提前增加空的独立调查页面。

## 4. 验证

测试覆盖3–5数量、唯一性、空建议、旧存档候选、自由/候选归一、切换后编辑、键盘提交、重复提交、stream/cancel/迟到事件、失败重试、草稿/待处理恢复、NPC候选与自由输入、冒险ACTION/DIALOGUE/OBSERVE集成以及既有持久化恢复回归。
