# Ember Tavern V0.3 Semantic Equipment

## 1. 目标与权限边界

M6-T02 把装备拆成两个互不替代的层次：AI 只提出名称、描述、类别、外观、历史、来源、剧情能力、语义效果、平衡标签和受限绑定；Rules Engine 只依据已锁定 World Constitution、当前 Quest 风险、奖励档位、推荐属性和装备类别派生 rarity、price、damage、defense、numeric effect 与 balance。叙事中的数字永远不进入规则计算。

SQLite 仍是唯一真实数据源。`GENERATE_ITEMS` 的结构验证成功只代表候选可进入本地裁决，不代表装备已经存在；只有原生结算事务同时验证生成审计、来源、Constitution 证据、绑定、去重和本地平衡后，才会写入装备、生成记录、事件与 Adventure ending。

## 2. 合同

`SemanticEquipmentDefinition` version 1 包含：

- `content`：name、description、category、appearance、history、origin、narrativeAbilities、semanticEffects；
- `mechanics`：rarity、price、damage、defense、numericEffect 和可审计 balance；
- `bindings`：精确的 Quest、NPC 或 World Fact ID、触发器与叙事说明；
- `constitutionEvidence`：锁定版本的 equipmentRules、technology、economy 原文；
- `source`：固定为当前已完成 Adventure 的 `QUEST_REWARD`；
- generation record、Constitution revision、Campaign 和创建时间。

绑定触发器为 `QUEST_CONTEXT`、`NPC_RECOGNITION`、`FACT_EVIDENCE` 和 `RELATIONSHIP_HOOK`。Quest reward 至少必须绑定当前 Quest 和一个发布者或关联 NPC；Fact 只能引用同一结算即将创建的确定性 Fact ID。未知、跨 Quest 或未授权绑定一律拒绝。

## 3. 本地平衡策略 version 1

Quest 风险给出奖励上限：LOW/BASIC、MODERATE/NOTABLE、HIGH/RARE、EXTREME/LEGENDARY。高于来源上限的装备不能落库。

| 类别 | 本地机械效果 | 价格因子 |
| --- | --- | ---: |
| WEAPON | damage = rarity rank | 3 |
| ARMOR | defense = rarity rank | 4 |
| TOOL | 当前 Quest 主推荐属性 `+1/+2` | 2 |
| CONSUMABLE | stress recovery `4/8/12/16`，一次 | 1 |
| CLUE | 无数值效果 | 0 |
| TREASURE | 无数值效果 | 5 |
| OTHER | 无数值效果 | 1 |

基础价格依次为 25、100、500、2500；透明预算依次为 2、4、7、10。数值效果只由上述表生成，不读取 name、description、history、semanticEffects 或 balanceTags 中的数值。

## 4. Generator 与结算

Windows 成功结算依次产生 `SUMMARIZE_ADVENTURE`、`GENERATE_WORLD_EVENT` 和 `GENERATE_ITEMS` 三个独立审计。装备输入携带当前 Campaign/Constitution revision、三项精确证据、Quest/Adventure 来源、奖励档位、已存在装备 ID/名称及允许绑定目标。Prompt 明确禁止输出 damage、defense、price、bonus、recovery 或 uses。

Native 在同一 `BEGIN IMMEDIATE` 事务中重新验证原始响应与结构输出一致、当前 Quest/Adventure 状态、风险上限、Constitution、绑定、Unicode 规范化 ID/名称去重和本地机械派生。任一失败都会回滚 Quest、关系、酒馆变化、装备、Fact、Clock、生成记录和结束状态。

## 5. 持久化、旧数据与存档

不新增第二张装备表。既有 `items.content_json` 保留顶层 `name`/`description` 兼容投影，并在 `semanticEquipment` 中保存完整 canonical 定义；`reward_tier` 和 `effect_json` 继续保存 Rules Engine 使用的数值投影。旧装备没有 `semanticEquipment` 时继续按旧合同读取。

既有 portable archive 已逐行携带 `items.content_json` 和 `effect_json`，因此嵌套语义对象无需升级 archive format 即可导出/导入。测试要求删除本地 Campaign 后导入仍保留语义内容和机械层，不得把普通本地重开冒充 portable round-trip。

M10-T05 之前的历史 portable v2 不携带 World Constitution。为保证其中进行中的 Adventure 仍可恢复，Native 只在锁定 Constitution 行确实缺失时，从已归档 World Bible 的 technology 建立带固定 `Legacy portable archive` 标识的保守兼容证据；economy 明确标为未知，机械仍只由本地 Quest 上限与策略派生。存在锁定 Constitution 时绝不使用该回退，回退也不会伪造或补写 Constitution 行。

## 6. UI 与范围

Adventure archive 继续展示兼容名称和描述，并可消费完整语义对象；后续装备 Game Component 应在既有 Item/Character/Adventure 边界上渐进展示 rarity、来源、能力和触发器。自然修改到的界面遵循视觉手册和现有 Design Token，不在 M6-T02 提前执行 M10-T07 Legacy UI 全量迁移。

本任务不修改 D20 硬结果顺序、Rules 事务状态机、Quest/NPC/Adventure 业务合同、Provider、World Seed、Career Pool 或 SQLite 作为唯一真相源的架构，也不进入 M6-T03。
