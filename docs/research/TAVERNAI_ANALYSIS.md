# TavernAI 分析

## 源码可用性结论

`SOURCE_NOT_PUBLIC_IN_THIS_REPO`。本轮固定仓库没有核心应用源码或 LICENSE，只有发布、翻译、文档镜像和社区材料。所有结论均为公开文档所描述的产品行为，不推断内部实现。

## 可借鉴机制

- Prompt Manager 把 prompt 当作有顺序、角色、位置、深度、启用规则和 token 成本的系统对象，而非字符串拼接。
- Preview 与真实发送使用同一装配路径，能解释实际输入；文件夹/分组只影响组织，不应悄悄改变语义。
- 自动、手动、空白发送区分“提交消息”和“触发生成”；重生成形成替代候选。
- 每角色 prompt、角色位置和本地/远端模型选择可改善可解释性。
- 多时间线概念证明共享事件身份与派生视图可以分离，但不是 v0.2 的必要范围。
- `zh-CN` 资源层说明核心界面应以资源键而非散落字符串实现。

## Ember 适配与限制

v0.2 实现统一 Context Inspector、候选重生成/编辑/接受、角色/世界/场景块和 token 预算。默认不显示 secret、完整系统提示或隐私块。完整分支聊天与 MultiChat 延后。
