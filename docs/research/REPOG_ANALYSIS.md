# RePoG 分析

## 可借鉴机制

- **因果回合脊柱**：Route → Resolve → Persist → Narrate，叙事只能描述已经解析并持久化的结果。
- **玩家作者权**：模型不能替玩家声明台词、动作、情绪、信念、信任或承诺。越界输出必须被校验拒绝。
- **知识边界**：NPC 只依据可观察事实、可靠来源和已发生揭示形成知识；“世界真相”不能自动变成角色知识。
- **冷热上下文**：当前真相、现场约束和未结后果保持 hot；历史正文按需从 cold 区检索。distill 不能延迟关键状态持久化。
- **SceneFrame/恢复**：场景模式、参与者、压力、未决后果和恢复锚点构成可续玩的最小帧。
- **幂等和连续性**：operation id、revision、重放保护与快照共同防止重复提交和陈旧写入。
- **一件事、多种主张**：事件、事实、主张、知识应分层，来源与可见性需要可追溯。

## Ember 适配

采用轻量 SQLite Event Ledger、结构化 ContextBlock、SceneFrame 与知识来源链。保留现有事务式状态模型，不引入完整事件溯源；distill 仅生成候选摘要，不能成为真实数据源。

## 不采用

- 不以 Markdown/YAML 文件系统替代 SQLite。
- v0.2 不实现完整 World Voices、长时自治 agent 工作区或 Session 0 框架。
- 不复制工作流文本或实现；只吸收可独立实现的约束。
