# Ember Tavern V0.3 Dynamic Quest Sources

## 1. 范围与权威边界

M8-T03 将已经提交到 SQLite 的世界变化适配为 Quest 内容生成请求。它不自动扫描所有玩家行为，也不承担 M8-T04 World Director 的调度、节奏判断或 M8-T05 的每日预算/冷却。

SQLite 仍是唯一真相源。NPC、Faction、Event、Discovery、Player Action 和 Consequence 只提供不可变的来源发生记录；Generator 只能返回 Quest 内容候选。来源种类、可见性、初始状态、发布者、事实白名单、预算和 provenance 均由本地代码决定，并在提交事务中重新读取和校验。模型不能创建来源、宣告任务可见、直接改变 Quest Pool，或引用未进入上下文的 NPC/事实。

玩家自由行为只在上层业务明确选择某个已提交的 `PLAYER_ACTION_SUBMITTED` 事件作为来源时调用适配器，因此“自由行为可产生任务”不等于“每个行为都创建任务”。自动选择何时创建留给后续 World Director。

## 2. 六类来源适配器

| 来源 | SQLite 发生记录 | 本地可见性 | 初始状态 | 生成上下文 |
| --- | --- | --- | --- | --- |
| NPC | 已提交的 `npc_timeline_operations` / 正式 NPC 回复 | 玩家可见 | `AVAILABLE` | 玩家意图、正式回复、当前公开 NPC 摘要 |
| Faction | `faction_action_events` | PLAYER 来源可见，其余隐藏 | `AVAILABLE` 或 `HIDDEN` | 行动种类、摘要、提案快照、关联 World Fact |
| World Event | `game_events` 的 `WORLD_CLOCK_ADVANCED` / `ADVENTURE_COMPLETED` | 玩家可见 | `AVAILABLE` | 事件类型与已提交 payload |
| Discovery | `game_events.FACT_DISCOVERED` | 玩家可见 | `DISCOVERED` | 被发现 World Fact 的 ID 与陈述 |
| Player Action | `game_events.PLAYER_ACTION_SUBMITTED` | 玩家可见 | `ACTIVE` | 已提交行动、Adventure/Turn 标识 |
| Consequence | 非空 `quest_graph_evaluations` | 隐藏 | `HIDDEN` | 本地求值触发与状态变化快照 |

NPC 来源只读取玩家已经看到的正式对话，不查询 `actor_knowledge`、NPC secret 或其他 Actor-private 数据。Discovery 只允许引用对应的已发现事实。所有 `relatedNpcIds` 必须来自本次公开 NPC 白名单，所有 `relatedFactIds` 必须来自适配器明确提供的 relevant facts。

## 3. 准备、生成与提交

一次显式创建按以下顺序执行：

1. Native 在 `TAVERN` 状态读取 durable occurrence，并投影规范化 source context；
2. 读取锁定的 World Constitution、当前公开 Quest 历史和公开 NPC；
3. 应用本任务的开放任务安全上限 12，并生成规范 JSON 的 SHA-256 `contextDigest`；
4. Windows 服务用完整 preparation 调用 `GENERATE_QUEST` prompt v3；
5. Native 在 `BEGIN IMMEDIATE` 中重新准备相同来源，精确比较 input、context 和 digest；
6. 重验输出 Schema、8–12 回合范围、NPC/Fact 白名单与重复 Quest 结构；
7. 原子写入 generation audit、Quest、Quest Pool 初始转换和 append-only provenance。

相同 `(campaignId, sourceKind, occurrenceId)` 只能产生一个 Quest。并发或重试先读取既有 provenance；完全相同的 generation identity 与 digest 可安全重放，不同输入复用同一来源则 fail closed。任何校验、预算或写入失败都回滚 creation intent、Quest、generation audit 和 provenance。

开放任务上限 12 是 M8-T03 adapter 的同步安全阀，只计算非终态 Quest，防止独立调用无限增长。它不是 World Director 的每日事件、紧急事件、NPC 主动、后台变化预算，也不包含恢复/冷却；这些仍严格留给 M8-T05。

## 4. 持久化与恢复

schema 25 新增：

- `quest_pool_creation_intents`：事务内一次性桥接 V0.3 初始状态与旧 `quests.status` 兼容列；Quest insert trigger 消费后立即删除；
- `dynamic_quest_sources`：每个动态 Quest 的 append-only 来源、发生 ID、实体、可见性、公开摘要、原始来源快照、事实白名单、context digest、generation record、预算快照和时间。

`dynamic_quest_sources` 对六类来源分别执行 Campaign/类型/实体 trigger 校验，禁止普通 update/delete。内部 save snapshot 包含 provenance，并在 restore session 中按外键顺序恢复；schema 25 前快照缺失该表时按空集合兼容。portable `.emtavern` format v2 不在本任务升级，正式跨版本归档仍由 M10-T05 处理。

## 5. 隐藏信息与投影

`HIDDEN` Quest 保留在 SQLite 和完整本地规则图中，但不进入 Quest Board 的 Quest 列表、最近标题、重复结构历史或 Windows 可调用的 Quest Graph 投影。可见图会删除以隐藏 Quest 为目标的边、隐藏 Quest 作为 Quest 来源的边、隐藏 Quest transition 触发的 evaluation，以及 evaluation 中的隐藏 Quest change/edge 引用。

这不会删除隐藏 Quest，也不会弱化本地 Quest Graph。Rules、事务重算和内部审计继续使用完整 SQLite 图；只有玩家/桌面读取边界执行投影过滤。

## 6. 与后续任务的边界

- M8-T04 决定何时提出世界变化或动态 Quest 调度建议，不直接写 Quest；
- M8-T05 持久化每日预算、冷却、优先级和恢复，不替换本任务的单次事务安全阀；
- M9 统一 Context Builder 时迁移本任务的 Constitution、公开 NPC、相关事实和 Quest 历史输入，不扩大知识可见性；
- M10-T05 负责 schema 25 portable archive；M10-T07 负责既有 Quest UI 的视觉迁移。

本任务不修改 Rules Engine、D20 硬结果、AI Provider、Generation Queue、World Seed、World Constitution、NPC/Quest/Adventure 业务合同或存档状态机，也不新增 UI/CSS。

## 7. 验收映射

- each source：TypeScript SQLite 集成覆盖六种 durable occurrence；
- dedupe：Repository、Windows 同源并发合并和 Native 重放覆盖；
- constitution：准备输入绑定当前 LOCKED revision，提交重算 digest；
- knowledge visibility：NPC private knowledge 不查询，Discovery facts 使用显式白名单；
- budget rejection：第 12 个非终态 Quest 后新来源 fail closed 且无部分写入；
- free action：显式 `PLAYER_ACTION_SUBMITTED` 来源生成 `ACTIVE` Quest；
- hidden quest：Native 创建 `HIDDEN` consequence 后，Quest Board/Windows graph 不投影，关闭重开仍保留 SQLite 事实。
