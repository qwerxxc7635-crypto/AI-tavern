# Ember Tavern V0.3 Performance Baseline

## 1. 证据身份

本报告是 M1-T04 的可重复性能基线，不是性能目标，也不用于证明真实网络或真实模型延迟。

- 记录时间：2026-08-13T14:22:29.761Z
- 源 commit：`589ef756c4df3b552a1b8c7cbf5b8da34c8793f5`
- 执行状态：M1-T04 工作树；源 commit 是开始本任务时已提交的 M1-T03 基线
- Provider 证据：**FAKE**
- 真实 Provider：**NOT_RUN**
- 环境：macOS arm64、Node.js v26.7.0
- 样本：每类任务 10 次，共 50 次

没有读取正式 API Key，没有调用真实模型 API。若未来获得单独授权，真实 Provider 结果必须另建 `REAL/RUN` 报告，不能覆盖或伪装成本报告。

## 2. 方法

基线工具通过现有 `FakeAIProvider` 执行 world、NPC、quest、action 和 D20 五类标准 AI 任务。每个样本测量从进入本地队列到完成的总延迟及队列等待时间；汇总采用 nearest-rank P50/P95。

为验证非成功路径，首个 quest 样本注入一个经过 `StandardAIError` 分类的受控 `TIMEOUT` 终态失败；首个 action 样本先经过同类可重试错误，再完成一次实际 Fake Provider 生成。两者均明确标记为受控场景，不代表 Fake Provider 自然故障率。

Fake Provider 不上报 token usage 或 prompt cache usage，所以输入 token、输出 token、cache hit token 和 cache miss token 都记录为 `null`（未知），没有伪造为 0。工具只持久化任务类型、证据类型、场景、成功状态、时间、用量计数、重试次数和安全错误码；不会持久化 Prompt、messages、玩家全文、request ID、凭据引用或秘密。

受控 quest 失败记录为 `FAILED/TIMEOUT`，延迟 0.152 ms、队列等待 0.026 ms。受控 action 重试记录为 `SUCCEEDED`、`retryCount=1`，延迟 1.128 ms、队列等待 0.018 ms。

这些亚毫秒到低毫秒数据只描述本机 Fake Provider、序列化和调度开销，不能外推为真实 Provider SLA。M12-T03 应使用同一 schema 与任务集合比较后续结果，不得把受控失败算作自然可靠性回归。

## 4. 重复运行

标准运行命令要求一个不存在的新输出路径，避免覆盖既有证据：

```bash
pnpm performance:baseline --output /tmp/ember-v03-baseline/report.json
```

可使用 1–20 次迭代做快速复核：

```bash
pnpm performance:baseline --output /tmp/ember-v03-baseline-repeat/report.json --iterations 3
```

本次另行完成 3 次/任务的独立重复运行，共 15 个样本；同样得到 `FAKE/NOT_RUN` 身份、一个受控 quest 失败、一次受控 action 重试和五类完整汇总。原始 JSON 只写到调用者指定的新路径，不默认加入仓库或应用遥测。

## 5. 门禁与解释规则

- schema 拒绝未知字段、负数、非有限数、超过 600 秒的时间、超过总延迟的队列等待，以及超过上限的计数。
- 成功样本不得携带错误码；失败样本必须携带格式受限的错误码。
- 单份报告限定 1–500 个样本，证据类型必须和所有样本一致；Fake 报告不得声称运行过真实 Provider。
- 汇总必须由样本重新计算并逐字段一致；unknown usage 传播为 `null`，不会被静默折算为 0。
- 本基线先于任何 M12 性能优化建立。后续优化必须保留失败语义、隐私边界与可重复方法。
