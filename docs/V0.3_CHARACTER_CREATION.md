# Ember Tavern V0.3 通用角色创建

状态：M5-T02 冻结合同

关联规格：`docs/V0.3_SPEC.md` 10.2 节

前置合同：`docs/V0.3_UNIVERSAL_CHARACTER_SCHEMA.md`

全局视觉规范：`docs/EMBER_TAVERN_VISUAL_STYLE_GUIDE_V1.md`

## 1. 目标与边界

M5-T02 在同一份 `UniversalCharacterDraft` 上提供 Quick 与 Advanced 两种入口。页面草稿、AI 输出和生成记录都不是正式角色事实；只有 `READY_TO_CONFIRM` 会话通过本地完整性校验后，确认事务才创建 `player_characters`、规则初始状态和 `universal_character_profiles`，并把 Campaign 推进到 `GENERATING_TAVERN`。

M5-T02 初始纵向切片保留两项叙事 Trait 和 V0.2 职业原型映射。M5-T04 在同一草稿合同上增加本地点数，M5-T05继续增加十维强度声明和协同验证：空集合或同时满足严格净0、透明点数档位及无组合套利时可以确认，其余状态保持为可编辑草稿。完整合同见 `docs/V0.3_TRAIT_POINT_SYSTEM.md`。

## 2. 持久会话

version 1 `CharacterCreationSession` 绑定唯一 Campaign、预分配 Character ID 和已锁定 World Constitution revision。状态为：

```text
ACTIVE ──本地完整性校验──> READY_TO_CONFIRM ──原子确认──> CONFIRMED
   │                              │
   └──────────暂停──────────────> CANCELLED
                                  │
                                  └──恢复──> ACTIVE / READY_TO_CONFIRM
```

- `revision` 和 expected revision 防止并发覆盖；数据库更新必须严格加一。
- `draft` 与 `lockedFields` 持久化到 SQLite，关闭应用或取消后可恢复。
- 会话身份、Character、Campaign、Constitution revision 和创建时间不可变；已确认会话不可编辑或删除。
- Native 保存使用服务端时间戳。普通保存不得创建或替换 Quick `generationRecordId`；该 provenance 只能由受验证的 Quick 提交路径写入。
- 锁定字段在保存、模式切换和 Quick 重生中保持原值；世界扩展字段使用 `extensions.<namespace>.<key>` 路径参与同一锁定合同。

## 3. Quick Creation

玩家输入一句概念，统一编排任务 `GENERATE_QUICK_CHARACTER` 接收概念、故事偏好、内容边界、锁定 Constitution 和扩展定义。输出只包含叙事共有字段、职业兼容映射、四属性优先级、两项默认 `NARRATIVE / 0` Trait、背景和世界扩展值。

Provider 不得输出财富、技能数值、派生属性、状态、装备 ID、关系、声望或机械加成。四属性由本地按唯一优先级分配为 4/3/2/1；Trait ID、Character ID、规则初始值和正式事实提交也全部由本地生成或裁决。结构验证、业务完整性校验和 generation audit 任一失败时不写正式事实。

Quick 候选可继续编辑。只要保存后仍完整且 provenance 有效，会话保持 `READY_TO_CONFIRM`；本地尚未保存的改动会禁用确认，避免确认旧的持久草稿。

## 4. Advanced Creation

Advanced 直接编辑所有通用叙事字段和当前 Constitution 声明的扩展字段。属性必须各为 1–5 且总和严格为 10；Rules/entity-owned 初始字段保持空值或零值，只读展示，不能从描述反解析。

“校验完整车卡”先保存当前草稿，再由本地合同检查必填叙事、目标、Trait 结构、严格净0、十维点数档位、协同套利、职业兼容映射、扩展 required 字段以及规则字段初值。空 Trait 集合合法；只有全部校验成功才进入 `READY_TO_CONFIRM`。

## 5. 确认事务与兼容性

确认在单一 SQLite immediate transaction 中完成：

1. 复核 Campaign、revision、会话状态、Constitution 和扩展定义；
2. Quick 模式复核 `GENERATE_QUICK_CHARACTER` 成功记录与 Campaign 归属；
3. 写入 V0.2 兼容角色行，由既有 trigger 建立规则初始状态和通用档案；
4. 只补入 V0.3-only 档案字段，不改写 trigger 已建立的规则 authority 投影；
5. 标记会话 `CONFIRMED` 并推进 Campaign。

任一步失败全部回滚；重复确认只在匹配当前或前一 expected revision 时幂等返回，不创建第二个角色。SQLite 本地关闭/重开已经覆盖；portable `.emtavern` 仍为 v2，新增表的跨语言导入导出统一留给 M10-T05。

## 6. UI 与后续边界

新页面复用现有角色创建布局、视觉 Token 和交互语言，以“命运编织”表达 AI 身份；没有创建第二套 Primitive 或 Game Component，也没有借本任务迁移旧页面。锁定控件与字段输入使用独立可访问标签。完整 Feature/Legacy 视觉迁移仍由 `docs/V0.3_VISUAL_MIGRATION.md` 和 M10-T07 收敛。
