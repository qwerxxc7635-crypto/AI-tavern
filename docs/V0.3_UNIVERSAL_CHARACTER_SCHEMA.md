# V0.3 Universal Character Schema

本文固定 M5-T01 的通用角色、世界扩展、V0.2 兼容投影与持久化边界。M5-T01 只建立可验证的数据基础，不提前实现 Quick/Advanced UI、Trait 点数或 AI 全字段生成。

## 通用角色档案

`UniversalCharacterProfile` schema version 1 以现有 `PlayerCharacter` 为一对一身份根，覆盖：

- 姓名、昵称、性别、年龄、身份、族群、出生地、阶层和信仰；
- 外貌、人格、价值观、目标、恐惧、秘密、家庭、教育、重要人物、敌人和经历；
- 概念、故事偏好、内容边界、职业、基础/派生属性、技能、熟练、能力和语言；
- 财富、装备、声望、关系、Trait、状态和世界扩展值。

基础属性继续由 M4-T03 Rules Engine 保护，通用档案更新不能改写它们。数值状态的实际演进仍以 `character_rule_states` 为准；档案中的技能名、财富和状态是该表的只读持久投影，Profile 写入必须与当前规则状态一致，规则事务会同步这些投影并推进 Profile revision。因此通用档案不会创建第二个 Rules authority。

通用合同为所有文本、集合、数字、Trait、装备和扩展设置资源上限并递归冻结。Profile 使用 expected revision 更新；角色/Campaign/createdAt/schema identity 不可改变。

## 世界扩展定义

世界特有字段不进入通用核心枚举。每个 Campaign 可注册最多 16 个 `WorldCharacterExtensionDefinition`，每个定义最多 32 个字段，并绑定一个已锁定的 World Constitution revision。

当前 schema version 1 支持：

- `TEXT`
- `INTEGER`
- `NUMBER`
- `BOOLEAN`
- `ENUM`
- `TEXT_LIST`

定义负责字段 key、玩家标签、required、数值范围、枚举选项或文本/列表上限。角色值必须精确匹配同 Campaign、同 namespace 和同 schema version 的定义；未知 namespace、未知字段、缺失 required 字段、未知版本和越界值均明确拒绝，不会被静默丢弃或解释为核心字段。

自动 fixture 覆盖：

- 修仙：灵根、境界、宗门；
- 调查：理智、幸运、信用；
- Cyberpunk：义体、神经负荷、街头声望。

这些只是可验证示例，不是硬编码进核心角色类型的世界闭集。后续世界可使用同一字段定义合同表达不同概念。

## SQLite 与 V0.2 兼容

schema 13 新增：

- `universal_character_profiles`
- `character_extension_definitions`

migration 13 为每个既有 `player_characters` 行保守创建 revision 1 通用档案。所有旧列和旧表继续保留；姓名、概念、偏好、内容边界、职业原型/显示名、属性、两项旧 Trait、个人目标、旧背景、装备和时间戳均可投影回原 `PlayerCharacter` 合同。旧写入口更新时，SQLite trigger 只同步对应兼容字段，并保留昵称、外貌、世界扩展等 V0.3-only 内容。通用档案仍可无损表示为 V0.2 时，Profile 更新也会在同一事务镜像旧行；不兼容档案不会截断数据或覆盖旧兼容面。

V0.3 允许未来出现零项、单项或多项 Trait，以及不映射四种旧职业原型的 Career；这类角色无法无损表示为 V0.2 时，兼容投影会明确拒绝，不会截断 Trait 或伪造职业。

## 恢复与当前限制

本地 schema 13 支持迁移、关闭重开、revision 校验和原生 Windows 启动。portable `.emtavern` 仍为 v2，当前不会导出世界扩展定义或完整通用档案；M10-T05 负责统一升级 portable schema、历史 fixture、跨语言 round-trip、损坏/中断恢复和字段完整性验证。在此之前不得把本地 SQLite round-trip 表述为 portable archive 已覆盖。
