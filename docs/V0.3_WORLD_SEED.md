# V0.3 World Seed

## 目标

World Seed 为程序化选择提供可重放、可隔离的随机输入。它不控制模型文本，不替代SQLite事实，也不能用于重投D20硬结果。

每个Campaign创建时在同一事务写入一个version 1 Seed。migration 10为既有Campaign一次性回填Seed；Seed记录由数据库trigger设为不可更新。

## 合同与算法

持久合同包含：

- `campaignId`；
- `schemaVersion = 1`；
- `algorithm = EMBER_STREAM_V1`；
- 128-bit小写十六进制`seed`；
- `createdAt`。

`EMBER_STREAM_V1`对`seed:streamId:position`执行固定的32-bit FNV-1a与avalanche混合。TypeScript和Rust共享测试向量，保证同一Seed、流名和position产生相同无符号32-bit值。该算法用于程序抽样，不是密码学随机源，也不是D20随机源。

算法名称属于存档合同；修改算法必须新增名称和显式迁移，不能静默改变version 1结果。

## 命名流与持久状态

每种用途使用独立流，例如：

- `map.initial`；
- `event.sample`；
- `npc.appearance`；
- `loot.semantic`。

`world_random_streams`按Campaign和stream ID保存下一position。Repository使用单条SQLite UPSERT原子预留1–4096次draw，并返回`startPosition + count`范围。另一个流的推进不会改变当前流结果；数据库关闭重开后从已持久cursor继续。

流ID只允许有限ASCII字符。`d20`、`dice`以及其命名空间在Domain、Repository、SQLite和Rust边界均拒绝，避免程序Seed伪装成受信硬随机。

## 可注入抽样工具

`DeterministicWorldRandom`只消费一个已预留范围，并提供：

- `nextUint32`与`nextUnit`；
- 有界候选`pick`；
- 非负有限权重`weightedPick`；
- Fisher–Yates `shuffle`。

范围耗尽后直接失败，不能无记录继续生成。调用方可以注入固定reservation进行测试，也可以由Repository从正式SQLite Seed/cursor预留。未来地图、事件和程序池消费者必须先预留用途流，不能调用全局`Math.random()`形成不可审计选择。

## SQLite事实与D20独立性

Seed只决定尚未落库的程序候选。候选一旦作为World Fact、实体、事件或其他游戏状态写入SQLite，后续加载必须读取该事实，不能用Seed重新计算并覆盖。Seed/cursor是选择输入与消费状态，不是事实的第二份副本。

D20继续只通过`D20RandomSource.nextD20()`进入现有硬逻辑，并将结果持久化后再生成叙事。`DeterministicWorldRandom`没有`nextD20()`；推进任意World stream不会改变注入的D20来源或已保存DiceResult。

## 边界

- 不声称LLM输出完全确定；模型温度设置与World Seed完全独立。
- 不提供玩家查看、编辑、复制或重置Seed的UI，避免把Seed变成重投入口。
- 本任务不提前实现地图、事件、装备或Director消费者，只提供持久且可测试的基础设施。
- portable archive表升级仍由`M10-T05`集中完成；本任务的save/reload验收为SQLite重开与migration回填。
