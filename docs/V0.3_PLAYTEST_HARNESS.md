## 3. 行为脚本

每世界固定 32 个按序动作，位于 `packages/test-fixtures/src/playability-worlds.ts`。脚本覆盖：

- Campaign 与角色创建、职业、Trait 和世界扩展字段；
- 酒馆、NPC 对话、传闻、有限认知和多 Quest；
- 自由输入、旅行、时间推进、D20、装备和交易；
- 两次保存/退出/重开以及最终状态复核。

动作只声明玩家输入和必须采集的证据类别，不声明预期剧情文本或预判结果。每项至少记录输出、延迟和状态摘要；Dialogue/Rumor、Quest、D20、Equipment/Economy、World、Save/Reopen 与 Free Input 会增加各自专用证据要求。

M11-T02～T04 必须实际执行各自脚本，记录真实结果并修复发现；不能把本 harness 的单元测试当成长测证据。

## 4. 隔离、重置与回放

`materializePlaytestRun` 为一次 run 创建以下结构：

```text
<output-root>/<run-id>/
├── manifest.json
├── fantasy/
│   ├── fixture.json
│   ├── script.json
│   ├── evidence.json
│   └── campaign.sqlite3       # 运行时创建
├── investigation/            # 同结构，独立 SQLite
└── cyberpunk/                # 同结构，独立 SQLite
```

Manifest 固定来源 commit、fixture SHA-256、script SHA-256 和组合 scenario hash。三个数据库路径彼此独立。相同源码与配置的另一 run 生成相同 scenario hash，但 evidence 从 `NOT_RUN` 重新开始，不复制前次结论。

`resetPlaytestWorld` 只清理被选世界的 `campaign.sqlite3`、WAL/SHM、动作流和 evidence；不触碰另两个世界。重置增加 `resetCount`，保持 fixture/script/hash 不变。路径、文件名和 run ID 均经过边界校验，禁止目录穿越和静默覆盖已有 run。

## 5. Evidence Format V1

每世界 `evidence.json` 使用 `EMBER_PLAYTEST_EVIDENCE` / version 1：

- `runId`、`worldKey`、`scenarioHash`、`sourceCommit`；
- `provider.mode` 明确为 `NOT_SET`、`FAKE` 或 `REAL`，并记录 Provider/Model 名称但不记录 Credential；
- `status` 为 `NOT_RUN`、`IN_PROGRESS`、`COMPLETE` 或 `BLOCKED`；
- 有序 action evidence：action ID、结果、latency、是否持久化、时间和逐类 observation；
- finding ledger：ID、P0–P3、标题、证据和 `OPEN/FIXED/DEFERRED/BLOCKED`；
- 重置次数、开始/完成时间和明确 blocked reason。

Evidence 必须严格按 script 顺序追加，并包含该动作要求的全部观察类型；Provider 身份在第一步后冻结。只有记录完 32 个动作才能标记 `COMPLETE`。`COMPLETE` 只表示测试执行完整，不表示没有失败或 finding。

## 6. 自动门禁

`packages/test-fixtures/src/playability-harness.test.ts` 覆盖：

- 三世界 fixture validity、实际业务合同验证和结构差异；
- 独立目录/数据库路径与不可变 hash；
- 单世界 reset 不影响其他世界；
- 同输入 replay 保持 hash 且不复制 evidence；
- 动作顺序、必需 evidence、Provider 冻结与 COMPLETE 门；
- fixture/evidence 秘密扫描与 hash 篡改 fail closed。
