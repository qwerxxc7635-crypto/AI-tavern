# Ember Tavern V0.3 — SillyTavern 功能审计

审计日期：2026-08-13

## 1. 审计范围与边界

本审计研究 SillyTavern 的产品能力和交互模式，用于确定 Ember Tavern V0.3 的采用边界。它不是源码移植计划，也不授权复制 SillyTavern 的品牌、图标、素材、文案、CSS 或实现。

审计依据：

- 官方当前 release：SillyTavern `1.18.0`（2026-05-03），以[官方 Releases](https://github.com/SillyTavern/SillyTavern/releases)和[官方仓库](https://github.com/SillyTavern/SillyTavern)为准。
- 本机参考包：`SillyTavern-1.13.3`，`package.json` 声明 `AGPL-3.0`；仅检查版本、License、README 标题和扩展目录，不读取兑换码、`secrets.json`、用户聊天或其他凭据/数据。
- 产品文档：SillyTavern 官方文档站的 Characters、Personas、World Info、Prompt Manager、Chat、Group Chats、Chat File Management、Connection Profiles、Summarize、Extensions 和 User Settings。
- Ember 基线：V0.2 当前代码、`docs/research/SILLYTAVERN_ANALYSIS.md`、两轮审计与可玩性报告，以及 `docs/V0.3_SPEC.md`。

### License 与安全结论

SillyTavern 主仓库采用 GNU AGPL v3。Ember 只采用可独立实现的产品思想和公开交互概念，不复制其源码或衍生实现。第三方依赖必须单独核对 License。

本机 1.13.3 包低于 1.17.0。SillyTavern 维护者在[第三方扩展安全事件公告](https://github.com/SillyTavern/SillyTavern/discussions/5592)中将 1.17.0 之前版本视为不安全并建议升级、检查扩展和轮换受影响密钥。因此该本机包只作为离线历史结构样本，**不得启动、联网、加载第三方扩展或复用其中凭据**。

## 2. 分类定义

- **Ember 已有**：V0.2 已存在且有代码/测试或审计证据。
- **Ember 缺失/不足**：V0.3 目标所需但当前不完整。
- **V0.3 采用**：吸收能力目标，在 Ember 自己的规则化、SQLite 架构和视觉体系内重做。
- **V0.3 不采用**：与不可刷新硬事实、安全边界或版本范围冲突。
- **后续考虑**：有价值但不进入 V0.3 核心交付。

## 3. 功能矩阵

| SillyTavern 能力 | 官方行为摘要 | Ember V0.2 已有 | Ember 缺失/不足 | V0.3 决策 | Ember 实现边界 |
| --- | --- | --- | --- | --- | --- |
| Character Card | [Characters](https://docs.sillytavern.app/usage/characters/)支持创建、编辑、搜索/标签、导入/导出、token 统计、单聊/群聊；Character Card 保存角色定义和扩展数据 | NPC profile、玩家车卡、结构化世界/角色、生成 Schema、SQLite 保存 | 玩家角色字段远少于 COC/DND 级；NPC 重要度与角色卡复用不足；无广泛卡格式兼容 | **采用核心能力** | 实现 Universal Character Schema、世界扩展、NPC LOD 和 Ember 自有导入/导出；不把外部自由字段直接视为规则事实 |
| Character definition / example dialogue | [Character Design](https://docs.sillytavern.app/usage/core-concepts/characterdesign/)区分 description、personality、scenario、first message、example dialogue、depth note 和 prompt override | NPC 身份、人格、目标、秘密、说话方式、上下文与记忆 | 角色定义编辑体验、示例对白、字段级 AI 辅助与锁定不统一 | **采用语义分层** | 将身份、人格、目标、说话方式、示例和世界事实分开；Core Rules 不可被角色 override |
| Persona | [Personas](https://docs.sillytavern.app/usage/core-concepts/personas/)把用户身份与角色分离，可绑定 chat/character、设置描述注入位置和 persona lore | 每存档有一个 PlayerCharacter；模型上下文含玩家状态 | 缺少同一存档多 persona/快速切换；角色创建与玩家身份层耦合 | **部分采用** | V0.3 将玩家角色视为强规则 Persona，并允许适合场景的角色视图/绑定；任意多 Persona 库延后，不能绕过 Campaign 角色事实 |
| World Info / Lorebook | [World Info](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)支持 global/character/persona/chat scope、关键词/递归/组、插入位置/顺序与预算 | WorldTruth/Claim/Knowledge/Memory 分层；Context blocks、预算、来源、revision、hash、Inspector | Lore 条目触发、优先级、scope 和独立编辑不足；世界知识仍偏固定投影 | **高度采用** | 建立结构化 World Lore、相关性触发、scope、priority、budget 和 future-RAG port；检索结果不是 Truth 授权 |
| Data Bank / RAG | [Data Bank](https://docs.sillytavern.app/usage/core-concepts/data-bank/)按 global/character/chat 文档 scope 管理资料，并可用 Vector Storage 检索 chunks | 无向量数据库；有结构化 Context 与未来检索 seam | 缺少文档库和可替换检索 port | **接口采用，向量实现延后** | V0.3 先做可解释的结构化/关键词/实体检索；外部向量服务不是发布前置，附件也不能成为世界事实 |
| Prompt Manager | [Prompt Manager](https://docs.sillytavern.app/usage/prompts/prompt-manager/)允许编辑、排序、启停不同 Prompt 块，并按 Normal/Continue/Swipe/Regenerate/Quiet 等触发器生效 | Prompt 目录/版本、稳定前缀、Context Manifest、Inspector、统一编排 | 无高级用户编辑入口；Core Rule 与 User Editable 的 UI 分层不足 | **采用控制力，限制权限** | 提供 User Editable 风格/辅助块、顺序预览和版本；Core Rule、Schema、Knowledge Boundary、hard result 不能删除或覆盖 |
| Text completion Context Template / Instruct | [Context Template](https://docs.sillytavern.app/usage/prompts/context-template/)和 Instruct Mode 可按模型模板组织 story string、persona、character、lore、examples 和 history | OpenAI-compatible Provider、Prompt profile、模型能力、稳定 prefix/dynamic tail | Provider/model 特定格式能力有限；尚无统一 V0.3 Generator Context | **部分采用** | Provider format layer 可替换，业务 Context 仍是规范化 blocks；不允许模板直接拼入秘密或绕过预算 |
| Presets | Prompt、采样、格式和连接可保存为命名 preset；不同配置有独立保存语义 | 设备模型 profile、默认/备用、randomness profile、Prompt version | 缺少面向玩家的组合 preset、版本/导入导出和原子切换体验 | **采用** | 解析为不可变 `ResolvedModelConfig` 后请求；preset 只保存引用/非秘密参数，Credential 仍在系统安全存储 |
| Connection Profiles / Model Settings | [Connection Profiles](https://docs.sillytavern.app/usage/core-concepts/connection-profiles/)保存 API type、model、URL、key selection、preset、template/tokenizer 等选择 | 统一设备模型设置、安全 Credential、probe receipt、默认/备用路由、真实 DeepSeek 验证 | 多任务 override 和命名组合体验有限；历史真人反馈曾出现页面与实际调用脱节 | **采用命名组合 UX** | Provider/credential 生命周期与 UI 分离；切换前冻结并验证 profile identity；不把 secret 写普通 settings |
| Solo Chat | [Chatting](https://docs.sillytavern.app/usage/chatting/)提供发送、流式停止、编辑、continue、消息 actions、文件管理 | NPC 连续对话、历史恢复、建议输入、关系、错误/恢复 | streaming、统一 Action Composer、AI 输入建议和多场景一致性不足 | **高度采用** | 对话统一 Composer、streaming/取消/状态、建议+自由输入；成功 NPC 回复成为不可刷新的世界历史 |
| Swipe / Regenerate / token reroll | Chat 可生成 swipes、编辑历史、regenerate；甚至可按 token alternative 局部重生 | 创建阶段候选；V0.2 有兼容重生成/快照能力 | 正式游戏若沿用 Swipe 会抹掉后果并与 SQLite 时间线冲突 | **正式游戏不采用** | 世界/车卡确认前允许刷新未锁定候选；进入游戏后只允许技术 Retry，且复用幂等键与硬结果 |
| Continue / auto-continue | User Settings 可启用 Continue、auto-continue、目标长度和流式停止 | 单次结构化生成；部分 Provider 支持流式能力字段 | 无成熟续写/流式 UX | **部分采用** | 长叙事可 streaming；Continue 只延展同一未提交生成，不创建第二个事实或改变已提交回复 |
| Edit/delete historical messages | ST 允许编辑、批量删除或隐藏消息并改变后续 Prompt | SQLite 消息/事件、快照和恢复 | 尚需明确世界时间线更正机制 | **不作为普通玩法采用** | 调试/数据修复必须生成更正事件并保留审计；玩家不能静默改写已经产生后果的历史 |
| Group Chat | [Group Chats](https://docs.sillytavern.app/usage/core-concepts/groupchats/)支持 manual/natural/list/pooled speaker order、mute、talkativeness、成员卡 swap/join | V0.2 主要单 NPC 对话；Adventure Context 可含多个 NPC | 缺少多 NPC 场景、speaker arbitration、打断/沉默/离开和 Actor 知识隔离 UI | **采用场景能力，不复制轮询** | Multi-NPC Scene 由性格、目标、关系、知识和场景规则决定参与行为；每个 Actor 得到独立授权 Context |
| Chat memory / Summarize | [Summarize](https://docs.sillytavern.app/extensions/summarize/)保存可编辑摘要、回滚、暂停、注入位置，并明确警告幻觉/遗漏 | Memory 有来源合同、摘要压缩、Context budget；Memory 不可升级 Truth | 长期人格/任务/世界的分层记忆生成与 UI 仍有限 | **采用可见性和回滚思想** | Structured Fact、Recent、Summary、Long-term Memory 分层；摘要保留来源和 revision，原始 SQLite 历史不删除 |
| Chat Vectorization | 向量化历史并检索相关消息，但官方文档也提示可能破坏 prompt cache 且不保证改善记忆 | DeepSeek stable prefix cache、Context budget/manifest | 无可替换历史检索；需要权衡缓存稳定性 | **后续考虑** | V0.3 先做结构化 relevance；只有基线证明收益超过 cache/复杂度成本才启用向量检索 |
| Branch / Checkpoint | [Chat File Management](https://docs.sillytavern.app/usage/core-concepts/chatfilemanagement/)把指定消息前历史克隆为 branch/checkpoint，可返回 parent | 自动快照、恢复中心、事件/SceneFrame、存档导入导出 | 缺少玩家可见分支导航；正式事实分叉语义未定义 | **Checkpoint 采用，平行世界分支后续** | V0.3 用技术快照处理恢复，不用 branch 撤销失败/死亡；未来平行时间线必须复制 Campaign 身份和事实库，不能覆盖原线 |
| Import / Export | Character Card、chat JSONL/text、settings/user backup 等多种资产可导入导出 | `.emtavern`、checksum、schema migration、secret scan、TS/Rust interop、原生文件对话框 | V0.3 新实体和 world schema 尚未升级；外部卡兼容有限 | **采用可迁移性** | 升级 `.emtavern` 与 V0.2→V0.3 migration；外部卡进入隔离验证/映射，永不携带 API Key |
| Context / Prompt inspection | ST 可查看 token、Prompt Itemization；Prompt Inspector 可在发送前查看/编辑 | Context Inspector 显示 block、source、revision、hash、budget、会话 cache 观察且遮罩 secret | 不显示 V0.3 Generator parse/repair/rules/persist 全链 | **采用可观察性，不采用任意编辑** | AI Inspector 增加 raw/parsed/validation/repair/metrics；Core Prompt、秘密和未授权 Truth 默认遮罩，Inspector 不写事实 |
| Generation loading UX | Chat 有 streaming FPS、Escape stop、auto-scroll、restore unsent input、加载/停止等设置 | 页面 loading/error、pending request、重开恢复、本地 hard-result 动画 | 各生成页面体验不统一；取消和 queue 状态不可见 | **采用一致交互** | Generation Panel + Queue 显示 queued/generating/validating/persisting，支持安全 cancel/retry；只有 committed 才展示为事实 |
| Quick Replies / STscript / Macros | Quick Reply、宏与 STscript 允许用户自动化 Prompt、消息和扩展行为 | 无用户脚本执行面；内部 use cases/ports 明确 | 缺少高级快捷动作，但引入脚本会扩大安全面 | **V0.3 不采用通用脚本** | 可提供受限 Action shortcuts/presets，必须调用正式 use case；任意脚本、SQL、HTTP、文件访问不开放 |
| Extension architecture | [Extensions](https://docs.sillytavern.app/extensions/)允许 built-in/third-party 扩展改变 UI/行为/内容；manifest 加载 JS；官方明确提示风险 | 包/port 分层、内部 extension seam；无第三方运行时代码市场 | 外部插件生态缺失 | **只采用内部可替换 seam** | V0.3 不开放第三方任意 JS/Server Plugin；先用 typed ports 替换 Provider、检索、Generator；插件市场后续且需沙箱/签名/权限模型 |
| UI customization / Visual Novel / media | 主题、MovingUI、Visual Novel、TTS、图像、翻译等成熟体验 | Ember 有多主题、桌面布局、zh-CN 和四分辨率 gate | 正式 Design System 和可访问性仍需重构 | **采用 Design System/可访问性思想；媒体不采用** | V0.3 做 tokens、primitives、responsive、motion/a11y；TTS、图像、视频和 Live2D 不在核心范围 |
| Multi-user / account backup | ST 可运行多用户服务器并管理账户、settings snapshots 和完整备份 | Ember 是本地单人桌面应用，有本地快照/备份 | 无账户/多人 | **不采用** | 保持单人、本地、设备级安全边界；不因参考 Web UI 引入服务器账户体系 |

## 4. 对 Ember V0.3 的核心采用清单

V0.3 必须达到的高覆盖能力：

1. 结构化 Character + Player Persona 语义分离，但角色数值和世界扩展由 Rules/SQLite 控制。
2. World Info 的 scope、priority、trigger、budget 和可解释 Context 组装。
3. Prompt/Connection/Preset 的高级控制力，同时冻结 Core Rules 和请求期 resolved config。
4. 成熟 Chat UX：streaming、cancel、恢复、建议+自由输入、生成阶段反馈。
5. Multi-NPC Scene，而不是简单把单聊复制成轮询群聊。
6. 分层 Memory、摘要可见/可追溯、完整本地历史保留。
7. Context/AI Inspector 和 token/cache/validation 可观察性。
8. 角色、世界、存档的安全导入导出与版本迁移。
9. 内部 typed extension seams，保持 Provider、Generator 和 Retrieval 可替换。

## 5. 明确拒绝与延期

### V0.3 明确拒绝

- 游戏开始后的 NPC Swipe、Regenerate 或静默历史编辑。
- 任意用户脚本、第三方 JS/Server Plugin 执行面。
- 前端保存或读取明文 API Key、直接 Provider HTTP、任意文件/SQL。
- 把自由文本 Lore、Memory 或导入 Character Card 直接升级为 WorldTruth/规则状态。
- 复制 SillyTavern UI、CSS、品牌、图标、默认角色、文案或 AGPL 实现。

### 后续版本考虑

- 完整外部 Character Card 格式矩阵。
- 真正的平行 Campaign branch/alternate timeline。
- 经过安全设计的插件/Mod 能力。
- 证据证明有净收益后的向量检索。
- TTS、图像、视频、Live2D 和多人服务器。

## 6. 审计结论

SillyTavern 最值得 Ember 学习的是“角色扮演上下文的可控性”和“生成交互的成熟度”，不是其可刷新聊天时间线或开放扩展执行面。Ember V0.3 应覆盖角色、Persona、World Info、Prompt、Preset、Context、Memory、Multi-character scene 和 Import/Export 的核心产品能力，同时以不可刷新硬事实、Rules Engine、Actor Knowledge、SQLite 事务和安全 Credential 形成清晰差异。
