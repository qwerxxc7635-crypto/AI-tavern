# V0.3 Rules Engine Expansion

本文记录 `M4-T03 Rules Engine Expansion` 的稳定合同、权限边界和已知限制。实现细节以代码与 migration 11 为准；后续任务不得绕过这些边界直接修改数值事实。

## 权限与事实边界

- SQLite 是角色数值状态、Quest 状态和规则事件的唯一真实数据源。
- 只有 `LOCAL_RULE`、`PLAYER_ACTION`、`SYSTEM` 三类本地 authority 可提交规则命令；合同和原生反序列化边界均不存在 AI authority。
- AI 输出只能进入既有 proposal/validation 流程。AI patch validator 显式拒绝全部规则命令和属性写入，叙事文本不得反解析为数值。
- 规则引擎不复制完整 DND、COC 或其他规则书，只提供 V0.3 当前需要的有界通用合同。

## Character Rule State v1

每个玩家角色拥有一个 `character_rule_states` 记录，包含：

- 不可变基础属性；
- 技能、HP、状态、已装备物品；
- 金钱、游戏内分钟；
- Trait 数值修正与通用资源；
- revision 和更新时间。

基础属性仍遵守既有五属性、单项 1–5、总和 10 的角色合同。数据库 trigger 同时禁止修改 `player_characters.attributes_json` 和规则状态中的基础属性副本。

## 有界命令

规则引擎只接受闭集命令：伤害/恢复、定义或变更技能、添加/移除状态、装备/卸下物品、金钱变更、推进时间、定义或变更资源、设置/移除 Trait 修正，以及 Quest 状态迁移。运行时严格拒绝未知命令、未知字段、非法 authority、越界数值、错误所属关系和不存在的引用。

主要边界为：技能 0–20、HP 最大 999、金钱 0–1,000,000,000、单次推进时间 1–10,080 分钟、资源值最大 999,999、状态/Trait 属性修正 -5–5。集合数量也有硬上限，防止无限生成放大。

M4-T03 只建立 Trait 数值修正的合法边界，没有提前实现 M5 能力。M5-T04随后增加角色创建点数与严格归零门禁，M5-T05再以显式十维声明和协同标签执行透明平衡；两者都不会自动创建`TraitRuleModifier`，也不从效果文本推导检定修正。详见 `docs/V0.3_TRAIT_POINT_SYSTEM.md`。

## D20、装备与 Quest

- D20 继续使用独立受信随机源；World Seed 不参与骰点。
- 检定修正由本地规则状态计算：基础属性、状态、Trait，以及角色实际拥有且已装备物品的 `CHECK_MODIFIER`。
- 物品数值效果在写入和读取时验证；叙事描述不能产生数值效果。
- Quest 使用共享的本地状态迁移表。角色状态、Quest 状态与审计事件在同一 SQLite 事务中提交。

## 事务、幂等与审计

`RulesEngineRepository.commitOnce` 和 Windows 原生命令均使用即时事务、expected revision 与 idempotency key：

- 首次成功提交同时更新规则状态、可选 Quest 状态并追加 `rules_events`；
- 相同 key 与相同 canonical command 重放时返回原事件，不重复生效；
- 相同 key 但不同 command、revision 漂移、事件冲突或任何校验失败会拒绝并完整回滚；
- `rules_events` 为 append-only，并保存命令、前后状态、revision、Quest 前后状态和时间戳，供本地审计。

状态与事件支持数据库关闭后重开恢复，Campaign 删除时随所属 Campaign 级联清理。

## 当前存档限制

本地数据库 schema 已升级到 11。portable `.emtavern` archive 仍保持既有 v2 格式，因此暂不携带新增的 `character_rule_states` 与 `rules_events`；其跨语言格式升级严格留在 `M10-T05 Save Migration` 集中处理。此前不得把本地 reopen 通过误报为 portable archive 已覆盖新规则状态。

## 后续边界

- `M4-T04` 才实现 Knowledge Boundary；本任务没有提前进入。
- 后续 Character、Trait、Quest、Adventure 功能必须复用现有命令、validator 和事务入口，不创建第二个数值写入口。
- 视觉规范只约束自然新增或修改到的 UI，不改变规则合同、事务、D20、Quest 状态机或存档兼容策略。
