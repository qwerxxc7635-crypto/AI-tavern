# Ember Tavern V0.3 Multi-Quest Pool

## 1. 真相源与兼容投影

`quest_pool_states` 是 V0.3 Quest 生命周期的唯一真相源。它允许同一 Campaign 同时存在多个可见、激活、阻塞或终结任务；任何调用方都不得再用单个 `currentQuest` 或“唯一主任务”推导世界状态。

既有 `quests` 表继续保存任务内容和 V0.2 状态列，后者只用于旧 Adventure/存档迁移兼容，不再是新代码的生命周期读取来源。旧入口只有在投影尚未分叉时才可同步；一旦 Quest Pool 已通过玩家介入等新路径推进，数据库拒绝旧状态覆盖。该兼容层不得删除终结任务，也不得改变 Quest、NPC 或 Adventure 的既有身份和外键。

## 2. 状态机

状态闭集为：

`HIDDEN` → `DISCOVERED` → `AVAILABLE` → `ACTIVE` → `COMPLETED`

并允许规则明确进入或离开 `BLOCKED`、`UPDATED`，以及进入 `FAILED`、`EXPIRED`、`ABANDONED`。`ACCEPTED` 作为 V0.2 兼容中间态保留，但不是激活任务的必要步骤。

完整合法边由 Domain、Rust Native 和 SQLite trigger 独立验证。`COMPLETED`、`FAILED`、`EXPIRED`、`ABANDONED` 是不可逆终态；生成、旧代码或其他系统都不能重开、改写或抹掉它们。每次成功转换必须使 revision 恰好加一，并使用新的 operation ID。

## 3. 来源与玩家介入

每次状态变化保存来源、原因、发生时间和幂等 operation ID。初始化、历史迁移、生成、玩家介入、玩家放弃、本地规则、系统、Adventure、Faction 与旧兼容入口使用不同来源。

玩家实际介入可把 `DISCOVERED`、`AVAILABLE`、`ACCEPTED` 或 `UPDATED` 直接推进到 `ACTIVE`，不需要传统“接受任务”门禁，也不取消其他 Active Quest。玩家只能放弃可见且尚未终结的任务；隐藏任务不能通过 UI 泄露。

自由行动、NPC、Faction 与世界事件如何创建 Quest 及保存更细 provenance 属于 M8-T03。本任务只提供可被这些适配器调用的、受本地规则保护的转换合同，不提前生成新的来源类型。

## 4. 持久化与事务

schema 23 新增：

- `quest_pool_states`：每个 Quest 一行当前状态、revision 和最后转换元数据；
- `quest_pool_transitions`：append-only 完整转换账本。
- `quest_pool_restore_sessions`：仅在自动快照完整恢复事务内存在的 Campaign 级重建门禁；提交或回滚后必须为空。

迁移从旧 `quests.status` 原样回填，包括已经失败或放弃的任务。新 Quest 插入时自动建立 revision 1 的初始化记录。Repository、Rules Engine、Faction、Adventure 开始和结算均在所属业务事务中修改 Quest Pool；失败时状态、业务结果和审计一起回滚。关闭并重开 SQLite 后当前状态和完整历史必须一致。内部自动快照保存并精确恢复 Pool 与账本；schema 23 前的内部快照缺少这些表时，从其中的旧 Quest 状态建立 revision 1 迁移记录。恢复会话不能绕过普通业务写入门禁。

portable `.emtavern` format v2 本任务不扩展；schema 23 表的正式跨版本归档升级仍由 M10-T05 统一完成。

## 5. UI 与视觉边界

任务页展示多个并存任务，隐藏 `HIDDEN`，允许多个任务同时 Active，并显示状态原因与 revision。玩家介入直接激活，现有 Adventure 准备入口继续复用已通过测试的 Quest/Adventure 合同。

本切片复用既有页面、按钮、卡片和 Design Token，不新增平行组件体系，也不逐页返工已完成 UI。完整视觉迁移与一致性审查仍由 M10-T07 按《Ember Tavern 视觉风格手册 V1.0》执行；视觉调整不得改变本文件的状态机、事务、终态不可逆或存档兼容合同。

## 6. 验收映射

- all states/transitions：Domain 全状态矩阵、Rust Native 与 SQLite trigger 测试；
- multiple active/implicit activation：Windows service/page 与 Native 集成测试；
- terminal preservation：Repository、Native 与迁移回归测试；
- save/reload/migration：schema 22 → 23 回填测试及 SQLite 关闭重开测试；
- cross-module atomicity：Rules Engine、Faction、Adventure 与结算专项测试。
