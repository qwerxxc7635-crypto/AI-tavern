# Ember Tavern V0.3 Prefetch

Status: M10-T02 implementation contract

Depends on: [`V0.3_LAZY_WORLD_GENERATION.md`](V0.3_LAZY_WORLD_GENERATION.md)

Global visual standard: [`EMBER_TAVERN_VISUAL_STYLE_GUIDE_V1.md`](EMBER_TAVERN_VISUAL_STYLE_GUIDE_V1.md)

## 1. Authority boundary

Prefetch prepares a provisional Location or Faction generation result. It never commits a Location, Faction, Quest, NPC, player action, World Fact, event, or lazy-generation success. The generated value exists only in the current process and becomes eligible for the original feature transaction only after an exact Campaign, kind, target, and Director context-digest hit.

SQLite stores prediction identity, lifecycle, invalidation, timing, and hit/miss metrics. It deliberately has no candidate payload, model output, prompt, private knowledge, or hidden source snapshot column. A process restart invalidates open candidates because their provisional bodies no longer exist.

## 2. Prediction and admission

Prediction consumes one admitted `WorldDirectorRun`, its current `DirectorBudgetSnapshot`, and schema-30 lazy plans. Only `BACKGROUND_ELIGIBLE` `LOCATION_DETAILS` and `FACTION_DETAILS` plans in `PLANNED` or retryable `FAILED` state are eligible.

- An approved Director proposal that resolves to an eligible target becomes P1 and retains only its action ID as admission evidence.
- Other eligible plans may become P2 up to remaining `backgroundChanges` capacity.
- One run produces at most four candidates, with stable Location-before-Faction and Unicode-codepoint target ordering.
- Deferred/rejected proposals cannot become P1. The Director source snapshot and proposal rationale/effects are never copied into a candidate.
- If any P0 lazy-world plan is not `SUCCEEDED`, planning invalidates speculative work and returns no candidates.

Schema 31 repeats the authoritative admission checks: matching Campaign/run/context digest, recorded budget admission, eligible lazy target, approved P1 action bound to the same actor/target, P2 capacity, and four-candidate cap. A failed batch rolls back its candidate rows and events together.

## 3. Scheduling and lifecycle

The application host injects the same `GenerationQueue` used by foreground generation. Prefetch submits P1/P2 jobs only; the queue retains its reserved background lane and always selects queued P0 first. Queue saturation records a content-free `PREFETCH_QUEUE_REJECTED` failure and does not displace or fail foreground work.

The lifecycle is:

`PREDICTED → RUNNING → READY → HIT`

with terminal `MISSED`, `INVALIDATED`, `CANCELLED`, or `FAILED` branches. Execution ownership, process identity, timestamps, error code, and revision are compare-and-swap protected. Events are append-only. New Director runs supersede older open candidates; P0 demand cancels and invalidates all speculative work; context drift invalidates rather than adopts.

Generation success only populates the coordinator's process-memory cache. Adoption returns the provisional value after SQLite records an exact hit. The caller must still use the existing Dynamic Location or Active Faction validation and commit transaction; prefetch does not add a second business path.

## 4. Metrics and privacy

Per-Campaign metrics count predictions, ready results, hits, misses, invalidations, cancellations, and failures, plus hit ratio and average queue/generation time. An unpredicted request records a miss without inventing a candidate. Metrics contain only bounded IDs, enums, timing, and target identity; no Prompt, response, generated content, credential, private Actor Knowledge, or Director source snapshot is persisted.

Internal snapshots preserve schema-31 lifecycle and events for audit and tolerate older payloads with empty prefetch collections. A restored READY row is not reusable after process restart because the body is intentionally absent. Portable `.emtavern` remains format v2; schema-31 cross-language archive migration belongs to M10-T05.

## 5. Boundaries

- No speculative result is a fact or evidence that an artifact exists.
- No route guessing beyond the finite schema-30 outline Location/Faction plan set.
- No change to Rules/D20, Provider contracts, World Seed/Constitution, Quest/NPC/Adventure state machines, or existing commit transactions.
- No UI/CSS is introduced. Future loading/metrics surfaces reuse existing tokens and components; complete Legacy convergence remains M10-T07.
