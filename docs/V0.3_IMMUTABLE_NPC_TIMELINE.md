# Ember Tavern V0.3 Immutable NPC Timeline

## 1. 目标与边界

正式游戏中的单 NPC 回复和 Tavern 多 NPC Scene Turn 一旦成功提交，就成为不可刷新的时间线事实。玩家界面不提供普通 Swipe、重新生成或删除后换结果；技术性 Retry 只用于传输、结构或明确事实冲突，不改变已经锁定的玩家意图、点名对象或 D20 硬结果引用。

本切片不改变 Rules Engine、D20、Quest、Adventure、NPC、Provider、Generation Queue、World Seed、World Constitution 或存档状态机。对话建议属于 M7-T04，portable archive 的 schema 21 表升级属于 M10-T05。

## 2. SQLite authority

schema 21 新增：

- `npc_timeline_operations`：保存 Campaign、`NPC_DIALOGUE`/`TAVERN_SCENE` Scope、玩家意图、点名 NPC、可选 `hard_result_key`、状态及最终提交引用。
- `npc_timeline_attempts`：按序保存每次技术尝试的 request、generation record 和 idempotency key 列表，以及失败分类和是否允许 Retry。

Operation 状态机为：

```text
PENDING → COMMITTED
PENDING → FAILED_RETRYABLE → PENDING
PENDING → FAILED_FINAL
FAILED_RETRYABLE → CANCELLED
```

意图、Scope、点名对象、硬结果引用、Operation identity 和已完成 Attempt 都由 SQLite trigger 锁定。应用中断后遗留的 `STARTED` Attempt 会先以 `APP_INTERRUPTED` 记为可重试失败，再在同一 Operation 下创建下一 Attempt。

## 3. Retry policy

只有以下失败允许技术性 Retry：

- Network：`TIMEOUT`、`NETWORK_FAILED`；
- Provider：`RATE_LIMITED`、`PROVIDER_UNAVAILABLE`；
- Validation：`INVALID_OUTPUT`、`REPETITION_DETECTED`、`SCHEMA_VALIDATION_FAILED` 和 `SCHEMA_*`；
- 明确事实冲突：`FACT_CONFLICT`；
- 应用中断恢复：`APP_INTERRUPTED`。

认证、配额、规则、持久化及未知失败默认进入 `FAILED_FINAL`。TypeScript Domain 和 Rust Native 各自计算同一白名单，调用者不能通过传入 `retryable=true` 放宽 Native policy。

Retry 使用同一 Operation、玩家意图、点名对象和 `hard_result_key`。每次 Attempt 使用新的 request/generation ID 以保留完整审计，但沿用首个 Attempt 的稳定 idempotency key；多 NPC Scene 保持 Actor 顺序及每 Actor 的稳定 key。Retry 不重新投掷 D20。

## 4. 原子提交与重复恢复

Windows 必须在调用 Provider 前创建持久 Operation/Attempt。Native 在 `BEGIN IMMEDIATE` 事务中重新构造 canonical Context，验证结构、事实、generation/request/idempotency 审计和 Scope 引用，然后同时提交：

- 单 NPC：pending request、generation record、玩家消息、NPC 消息、关系/情绪/记忆后果和 Timeline；
- 多 NPC：全部 pending request/generation record、Actor proposal、本地仲裁、Scene Turn/revision 和 Timeline。

任何一步失败都不留下部分消息、部分 Actor proposal 或已提交 Timeline。若 Native 已提交但响应通道丢失，Windows 读取 durable `COMMITTED` 状态并重载 SQLite 结果，不再次提交。对已提交 Operation 的 begin/replay 只返回封存结果，不创建新 Attempt。

schema 21 的消息触发器只保护由正式 Timeline 提交的 NPC 回复及其紧邻玩家输入，避免改写或删除，同时不把 M7-T03 之前的普通历史消息误纳入本任务，也不破坏旧快照兼容路径。

## 5. UI 规则

- `NpcDialoguePage` 和 Tavern Scene 不显示 Swipe、刷新成功回复或“换一个结果”。
- 失败 UI 的 Retry 调用专用 `retry()`，不能重新调用 `send()` 生成新意图。
- 页面重载发现 `PENDING` 或 `FAILED_RETRYABLE` 时显示恢复入口；新输入在未解决 Operation 存在时被拒绝。
- 已提交 Timeline 不显示 Retry；自由输入在没有未解决 Operation 时继续可用。
- 自然触及的 UI 继续复用 `ActionComposer`、`DialogueView`、`NpcCard` 与现有 Design Token；不提前执行 M10-T07 Legacy UI 迁移。

## 6. 验收覆盖

自动测试覆盖成功封存、消息 append-only、network/schema/fact retry policy、非技术失败终止、应用中断恢复、锁定意图/硬结果、防重复提交、响应丢失恢复及多 NPC Actor 顺序。Native 同时验证 Timeline 引用确实属于目标 NPC 对话或目标 Tavern Scene，AI 输出不能自行指定另一个提交事实。
