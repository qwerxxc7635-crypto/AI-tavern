# Ember Tavern V0.3 Trait Point System

状态：M5-T04 / M5-T05 冻结合同

关联规格：`docs/V0.3_SPEC.md` 10.3 节

前置合同：`docs/V0.3_CHARACTER_CREATION.md`、`docs/V0.3_RULES_ENGINE.md`

全局视觉规范：`docs/EMBER_TAVERN_VISUAL_STYLE_GUIDE_V1.md`

## 1. 权限边界

Trait 点数是本地规则，不是生成内容的自评分。AI 可以为当前类型补写正面或负面效果文本，但不能选择 Trait 类型、分配点值、确认净点数或绕过开始门禁。SQLite 保存完整 `pointProfile`；任何显示值、AI 文本或序列化输入都必须再次经过 TypeScript 合同、Domain 规则和原生 Rust 边界验证。

M5-T04判断点数结构与严格归零；M5-T05以显式结构评估效果强度、公平性、触发频率、条件覆盖和Trait组合协同。两阶段都不从自然语言反解析数值，也不让AI成为最终裁决者。

## 2. 合同

每项 Trait 可携带 version 1 `pointProfile`：

| 类型 | 正面效果 | 负面效果 | Buff 点 | Debuff 点 |
| --- | --- | --- | ---: | ---: |
| `BUFF` | 必填 | `null` | -5 至 -1 | 0 |
| `DEBUFF` | `null` | 必填 | 0 | +1 至 +5 |
| `MIXED` | 必填 | 必填 | -5 至 -1 | +1 至 +5 |
| `NARRATIVE` | `null` | `null` | 0 | 0 |

合同拒绝未知类型、未知字段、非整数、越界、错误符号、空效果和与类型矛盾的效果。`net` 不持久化，始终由 `buffPoints + debuffPoints` 本地计算；角色总点数是所有 Trait 净点数之和。

旧存档中缺少 `pointProfile` 的 Trait 按 `NARRATIVE / 0` 读取。这是只读兼容默认，不允许将带数值效果的旧描述反解析为点数。

## 3. 开始门禁与空集合

角色草稿可以保存非零或尚未完成的点数配置，以支持逐步编辑；此时会话保持 `ACTIVE`。进入 `READY_TO_CONFIRM` 及正式确认时，TypeScript 与 Rust 都必须重新验证全部 Trait，并要求角色总点数严格等于 0。

空 Trait 集合的总点数定义为 0，因此可以开始。当前角色创建页面延续既有纵向切片，最多编辑两项 Trait；共享合同和持久层允许 0 至 32 项，避免把 UI 上限误作领域规则。

## 4. UI 与 AI

角色创建页直接显示 Domain 规则的本地重算结果，并在配置非法或净点数非零时禁用“校验完整车卡”和确认。保存草稿保持可用，移除全部 Trait 后重新回到合法的净 0 状态。

类型选择与点数下拉框完全由玩家和本地规则控制。只有当前类型实际存在的 `positiveEffect` / `negativeEffect` 进入 M5-T03 的 `AIFieldAssist` 白名单；应用候选后再次比较类型和两类点数，任何变化都以 `RULE_AUTHORITY_CHANGED` 拒绝。界面继续复用现有角色创建布局、Design Tokens 和共享辅助组件，不建立第二套 UI 体系，也不提前执行 M10-T07 Legacy 迁移。

## 5. 序列化与兼容性

`pointProfile` 随既有角色和创建会话 JSON 持久化，不新增 SQLite 表或 schema migration。TypeScript Repository、SQLite 关闭重开和 Rust Native 创建/确认路径均验证同一结构与严格归零规则。

V0.2 `PlayerCharacter.traits` 从固定二元组兼容演进为数组，使 M5-T04 明确要求的空集合可以进入既有角色根记录。旧两项 Trait JSON 不变且继续读取；V0.3 Profile 投影只保留旧根字段 `id/name/description`，点数详情仍由完整 Profile 保存，不伪装成旧字段。portable `.emtavern` 仍是 v2，完整 V0.3 档案迁移继续留在 M10-T05。

## 6. 十维平衡声明

每个机械正面或负面效果必须分别持久化一份`TraitEffectBalanceDeclaration`。策略版本1固定十个维度及其0至3序数：

| 维度 | 0 | 1 | 2 | 3 |
| --- | --- | --- | --- | --- |
| 频率 | 罕见 | 偶尔 | 常见 | 持续 |
| 环境 | 单一场景 | 有限 | 广泛 | 通用 |
| 战斗 / 社交 / 剧情 / 经济 | 无 | 轻微 | 显著 | 主导 |
| 永久性 | 瞬时 | 场景 | 持续 | 永久 |
| 可规避性 | 容易 | 有代价 | 困难 | 无法规避 |
| 效果稀有度 | 常见 | 少见 | 稀有 | 独特 |
| 条件覆盖 | 严格 | 特定 | 宽泛 | 无条件 |

十项相加得到0至30的可见总分；`0–5 / 6–11 / 12–17 / 18–23 / 24–30`分别对应1至5点。至少一个战斗、社交、剧情或经济影响必须非零；条件不是“无条件”时必须声明所需条件标签。正面效果的Buff绝对值和负面效果的Debuff值都必须精确匹配建议档位，不能用隐藏权重、文本猜测或AI自批覆盖。

`TraitBalanceReport`保存策略版本、绑定的`campaign@constitutionRevision`、逐效果十维breakdown、总分、建议点数和精确字段路径。相同声明、策略版本和锁定世界规则产生字节稳定的同构报告；标签使用确定性排序，不依赖系统locale。

## 7. 协同与组合套利

每个效果除十维外显式声明机制、授予、所需和抵消标签。`TraitSynergyValidator`只裁决可由结构证明的明显套利：

- 正面效果抵消任一用于换取点数的负面机制；
- 正面效果集合自行提供另一正面效果声称需要的条件，且该条件原本让点数落入更低档；
- 两个正面效果形成相互授予条件的自维持闭环。

仅共享主题或机制标签不会自动失败，避免把普通角色构筑误报成套利。验证器返回稳定issue code、Trait ID、目标路径和解释；`TraitGenerationFeedback`把Balance与Synergy报告组合为可供生成修复使用的accepted/issues结构，但AI只能提出修改，最终重新计算仍由本地规则执行。

## 8. 编辑、确认与旧数据

角色页面在正面和负面效果下分别提供十维选择与机制标签编辑，并实时显示本地建议档位、平衡/协同状态和中文解释。非零、档位不符、声明缺失、声明损坏或组合套利都会禁用准备与确认，但保存草稿保持可用。

M5-T04已写入但缺少十维声明的机械Trait保持可读取、可恢复和可补全，不静默伪造评估；它在重新准备或确认时明确失败。旧Narrative 0、空集合和既有两项叙事Trait无需迁移。声明仍嵌入现有Profile/会话JSON，SQLite schema保持14；TypeScript与Rust Native使用相同枚举、分档、标签边界和确认门禁。
