# Ember Tavern V0.3 UI Primitives

## 1. 范围

`windows-app/src/ui/primitives.tsx`提供无业务状态的React primitives：Button、Input、Textarea、Select、Card、Modal、Drawer、Tabs、Tooltip、Toast、Skeleton、Progress、EmptyState和ErrorState。样式集中在`ui/primitives.css`，只消费M2-T01的Semantic/Component token，不包含hex/rgb颜色。

本任务没有引入shadcn、Radix、Tailwind、表单库或额外状态库。现有React、原生HTML和CSS已足以满足当前组件范围；等未来出现原生`dialog`或本地Tabs无法可靠覆盖的明确问题证据时，再独立评估依赖。

## 2. 统一状态合同

- Button：默认`type=button`；primary/secondary/quiet/danger四种视觉语义；loading时使用可见中文状态、`aria-busy`并与disabled共享不可点击合同。
- Input/Textarea/Select：label为必填prop；description与error生成稳定关联ID；错误同时提供文本、`role=alert`和`aria-invalid`，不只依赖颜色。
- Card：标题通过`aria-labelledby`命名section；header/content/footer结构稳定，不能承担数据读取或保存。
- Modal/Drawer：使用原生`dialog`和`showModal`；打开时聚焦调用方指定控件或首个可交互控件，Esc、关闭按钮和backdrop只发出`onClose`意图，实际open状态由调用方拥有；关闭后焦点回到触发控件。
- Tabs：使用tablist/tab/tabpanel原生ARIA模式；仅活动tab进入Tab序，方向键循环、Home/End跳转，并跳过disabled tab。
- Tooltip：把tooltip ID合并到原生触发器的`aria-describedby`；hover和focus-within都可见，不制造额外键盘停靠点。
- Toast：普通/成功使用polite status，错误使用assertive alert；颜色之外保留title与description。
- Skeleton：装饰行对辅助技术隐藏，单独提供status文本和`aria-busy`；行数限制为1–12。
- Progress：使用原生progress与label；拒绝负值、非有限数、零max和越界值。
- EmptyState/ErrorState：空状态保持普通section；错误状态使用alert，可显示安全错误码和调用方提供的action。

## 3. 无障碍与视觉合同

- 所有交互元素优先使用原生button/input/textarea/select/dialog/progress，不以div伪造控件。
- button、field与tab最小高度44px，超过WCAG 2.2 AA的24px target size；Tooltip不能成为唯一信息来源。
- `:focus-visible`使用主题focus token，带3px offset与scroll margin，避免被粘性内容完全遮挡。
- 两个主题共用同一组件CSS；Paper主题只替换Semantic token。forced-colors模式恢复系统边框与Highlight选中态。
- reduced-motion关闭spinner、skeleton及组件transition，不改变loading、timeout或业务完成条件。
- Modal/Drawer正文可滚动，drawer在窄窗口使用`100vw`约束；Toast使用正式toast layer，不以任意z-index覆盖Modal。

## 4. 渐进迁移

M2-T02只将`AppErrorBoundary`迁移到ErrorState，证明primitive可以进入现有页面而不改变错误边界语义或路由。其他页面继续保留已有控件，后续按组件族迁移：

1. M2-T03先迁移重复Game Components，不做全仓机械替换。
2. 表单迁移时必须把现有label、description、error和disabled/loading状态逐项映射，不能只替换标签。
3. Overlay接入时由页面保留业务状态与保存动作；primitive只能发出用户意图。
4. Toast/Error接入统一沿用M1-T03六类错误合同，不在primitive中判断Provider、规则或fallback。

## 5. 验证

行为测试覆盖click/loading/disabled、三类表单label/error、Card结构snapshot、Modal焦点与关闭、Drawer、Tabs键盘、Tooltip描述、Toast live region、Skeleton、Progress边界和Empty/Error语义。CSS静态测试覆盖token完整性、44px target、focus、dialog backdrop、drawer、reduced-motion与forced-colors；既有AppErrorBoundary回归证明迁移没有暴露原始异常。
