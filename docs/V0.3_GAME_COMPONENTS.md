# Ember Tavern V0.3 Game Components

## 1. 权威清单

原始V0.3目标与`docs/V0.3_SPEC.md`明确列出十类组件：CharacterCard、NpcCard、TraitCard、QuestCard、ItemCard、ActionComposer、DialogueView、AIFieldAssist、GenerationPanel和StatusPanel。`docs/TASKS.md`中“九类”是计数文字漂移；本任务以明确名称为准，十类全部提供。

组件位于`windows-app/src/ui/game-components.tsx`，只接收只读view model、ReactNode和用户意图callback，不导入Repository、SQLite、Tauri、Provider、AI orchestrator或领域规则。样式位于`game-components.css`，只使用正式token。

## 2. 组件边界

- CharacterCard：人物名称、职业、摘要、等级/状态投影和外部action插槽。
- NpcCard：姓名、身份、情绪、居住类型及受控selected/disabled/onSelect。
- TraitCard：名称、说明、类别及原生checkbox；选择结果只通过boolean callback返回。
- QuestCard：标题、摘要、风险、发布者、状态及受控选择。
- ItemCard：名称、类别、说明、可选效果/数量和外部action。
- DialogueView：按PLAYER/NPC/SYSTEM渲染消息，并统一loading/empty/error；不读取或发送对话。
- ActionComposer：建议按钮、永久自由Textarea和显式submit callback的展示壳。M2-T05才负责模式、streaming、重复提交、恢复及NPC/冒险/调查统一。
- AIFieldAssist：IDLE/LOADING/CANDIDATE/APPLIED/ERROR/LOCKED展示合同。M2-T04已补齐生成/完善/候选/扩写/缩写、采用/撤销、重试、竞态与锁定；生成器接入由页面/Application提供。
- GenerationPanel：有界阶段、原生Progress、retry/cancel意图；不启动生成任务。
- StatusPanel：label/value/tone投影和空状态；不计算属性、时钟或规则结果。

## 3. 迁移

M2-T03迁移三处现有重复实现：

- 任务板的委托按钮改用QuestCard，页面继续拥有selected quest与accept业务。
- 酒馆人物列表改用NpcCard，页面继续拥有选择与导航。
- NPC对话历史改用DialogueView，页面继续拥有草稿、建议话题、发送、错误与关系状态。

旧CSS类作为`className`传入以保持页面布局，新的`is-selected`结构边线同时提供非颜色选择提示。其余角色特质、物品、冒险状态将在对应业务任务迁移，避免一次性重写。

## 4. 状态与无障碍

五类Card使用article/原生button/label+checkbox语义。选择同时提供`aria-pressed`或checked、边框和inset marker；窄窗口下人物/物品卡降为两列，消息宽度提高到92%但不占满整行。Dialogue使用polite live region；loading/empty/error复用M2-T02 primitives。forced-colors选中态使用系统Highlight。

## 5. 验证

组件测试覆盖十类渲染、五类Card选择、Dialogue四态、ActionComposer建议/自由输入/提交、AIFieldAssist意图、Generation retry/cancel与Status投影。CSS测试拒绝raw颜色和未定义token，并验证760px窄窗与非颜色选中标记；三份现有页面测试验证迁移后的真实交互回归。
