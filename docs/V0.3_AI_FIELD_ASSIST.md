# Ember Tavern V0.3 AI Field Assist

## 1. 统一合同

自然语言字段使用同一组六种操作：生成、完善、多个候选、扩写、缩写和锁定。`ai-field-assist-state.ts`是纯状态机，正式阶段为`IDLE → GENERATING → CANDIDATE → APPLIED`，并具有`ERROR`和`LOCKED`分支；`AIFieldAssist`只投影状态和用户意图。Provider、Repository或SQLite均不进入组件。

生成结果必须先成为1–5个候选；“多个候选”至少需要2个。候选非空、去重、最多8000字符且拒绝危险控制符。字段值在`RESOLVE`后不改变，只有玩家显式“采用候选”才进入`APPLIED`。React适配器此时才调用字段的`onValueChange`；生成器没有保存回调或游戏状态写入口。撤销恢复采用前的值并再次通过同一字段回调。

每次请求具有独立ID和AbortSignal。生成中拒绝第二次生成和编辑；取消会abort并清除活动请求，迟到、失序或已取消响应按ID忽略。错误只投影稳定码，不显示Provider原始异常；重试复用上次操作但创建新请求ID。

## 2. 字段清单

权威清单位于`windows-app/src/ai-field-inventory.ts`，共21个现有自然语言输入：

- 世界创建草稿：世界构想、不希望出现内容。
- 世界预览/修订：名称、当前地区、简介、核心冲突、技术水平、力量规则、叙事风格、禁止设定、酒馆原因、自然语言修改要求。
- 角色创建：名称、性别、角色概念、职业名、个人目标、剧情偏好、内容禁区。
- 自由行动：NPC对话与冒险输入；二者由M2-T05的Action Composer实现统一候选/提交生命周期。

每个输入在所属页面标有唯一`data-ai-field`，自动审计验证清单ID唯一、所有者唯一、源文件恰有一处登记，并拒绝未登记的字面marker。配置值、枚举、数值、搜索和系统诊断不属于自然语言创作字段，不进入清单。

## 3. 锁定与事实边界

软锁可以由拥有页面解锁；硬锁不可逆，拒绝编辑、生成和解锁。世界预览沿用现有`lockedFields`作为页面事实投影，世界确认/游戏开始后的锁定事实不得通过字段辅助刷新。状态机清除锁定时尚未采用的候选，且不允许在活动请求期间锁定，避免请求完成后越过锁。

M2-T04只建立统一合同、组件、适配器和完整字段所有权，不伪造候选，也不提前新增真实模型调用。M3的Generator Framework接入时只能实现`generate({ operation, value, signal }) → candidates`这一无持久化接口；结构/业务验证仍需在Generator/Application边界完成。

## 4. 验证

专项测试覆盖21字段审计、完整生命周期、采用前不发布、撤销、取消和迟到响应、并发生成/编辑、重试、软/硬锁，以及空值、重复、数量、控制符和长度越界输出。组件测试覆盖六种操作与IDLE/候选/APPLIED/ERROR/LOCKED展示；适配器测试证明Provider完成不会直接发布字段值。
