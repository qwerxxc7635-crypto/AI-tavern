# Ember Tavern V0.3 Quest Graph

## 1. 权威边界

Quest Graph 是 Campaign 内的本地确定性依赖图。SQLite 中的 Quest Pool、World Fact、NPC、Faction 与 Location 是唯一输入真相；AI、Generator、UI 和调用方只能提交图配置候选或请求重算，不能宣告依赖是否满足，也不能直接提交目标 Quest 状态。

图只改变 `quest_pool_states`，不改写 Quest 内容、NPC、Faction、Location、World Fact、Adventure 或 D20 结果。所有变化继续经过 Quest Pool 的合法转换与终态不可逆门禁。失败时图配置、Quest 状态和审计事件在同一 `BEGIN IMMEDIATE` 事务中回滚。

## 2. 边与谓词

边分为：

- `PREREQUISITE`：同一目标 Quest 的全部前置边采用 AND；满足与不满足时的状态政策必须一致；
- `CONSEQUENCE`：谓词满足时产生一个带显式 priority 的状态候选。

来源和合法谓词为：

| 来源 | 谓词 | 值 |
| --- | --- | --- |
| Quest | `STATUS_EQUALS` | QuestStatus |
| World Fact | `EXISTS` | `TRUE` |
| NPC | `STATUS_EQUALS` | 本地 NPC 状态，如 `DECEASED` |
| Faction | `MATERIALIZATION_EQUALS` / `PLAYER_RELATION_EQUALS` | materialization 或关系闭集 |
| Location | `MATERIALIZATION_EQUALS` | `OUTLINE` / `DETAILED` |

每条边的来源与目标必须属于同一 Campaign。语义重复边、悬空引用、非法来源/谓词组合和 Quest→Quest 循环均被 Domain、Repository/Native 与 SQLite 外键/trigger 分层拒绝。

## 3. 确定性求值

Quest→Quest 边先生成稳定拓扑序；同级按稳定 Quest ID 排序。求值期间，前序 Quest 的本地规则变化立即进入内存状态，因此 A→B→C 可在一次事务中传播。

同一目标的前置边作为一个候选，priority 取该组最高值；满足的后果边分别成为候选。最高 priority 获胜；相同 priority 若要求不同状态则拒绝整次求值，不用数组顺序或模型判断打破平局。已经处于 `COMPLETED`、`FAILED`、`EXPIRED` 或 `ABANDONED` 的 Quest 永不被图重开或覆盖。

Quest Pool 根转换会在所属事务内触发 `QUEST_TRANSITION` 求值；Faction 行动完成其状态/事实修改后触发 `FACTION_CHANGE` 求值。其他本地事实或实体事务使用同一 Native 重算入口并声明 `WORLD_FACT_CHANGE`、`NPC_CHANGE`、`LOCATION_CHANGE`；维护和调试可显式使用 `MANUAL_REEVALUATION`。M8-T03 后续来源适配器必须复用该入口，不得复制状态机。

## 4. 持久化、审计与恢复

schema 24 新增：

- `quest_graphs`：Campaign 当前图 revision；
- `quest_graph_edges`：当前权威边；
- `quest_graph_revisions`：每次图替换的 append-only 完整边快照；
- `quest_graph_evaluations`：触发来源、图 revision、参与边及状态变化的 append-only 求值事件。

图替换使用 expected revision 和 operation ID；相同输入可幂等重放，复用 operation ID 的不同输入被拒绝。每项图驱动状态变化都以 `LOCAL_RULE` 写入 Quest Pool，并保留触发 evaluation、边 ID、原因、时间及其自身 Pool transition。

内部自动快照保存并精确恢复当前图、图修订和求值历史。schema 24 前的内部快照恢复为空图 revision 1；关闭重开 SQLite 后图、状态和审计保持一致。portable `.emtavern` format v2 本任务不扩展，schema 24 的正式跨版本归档仍由 M10-T05 处理。

## 5. 调试投影与视觉边界

Quest Board 快照携带图和最近 20 次求值。页面在折叠的“任务关系调试”区域显示来源、谓词、目标、结果和最近变化数；它只投影 SQLite 数据，不提供绕过规则的编辑入口，也不泄露隐藏 Quest 内容。

本任务复用现有 Quest 页面和视觉 Token，没有新增 CSS 或平行 Game Component。完整 Feature/Legacy 迁移与视觉一致性审查仍由 M10-T07 按《Ember Tavern 视觉风格手册 V1.0》执行；调试投影后续迁移不得改变图、Quest Pool 或审计语义。

## 6. 验收映射

- chain/branch：Domain 与 TypeScript/Rust 事务集成覆盖 A→B→C 和 A→B/C；
- NPC/Faction/Location/Fact：Repository 使用真实 SQLite 实体状态覆盖全部来源；
- cycle/dangling/policy conflict：Domain、Repository、migration trigger 覆盖并验证无部分写入；
- rollback/reload：非法替换保持 revision/边/事件不变，合法传播在关闭重开与内部快照恢复后保持；
- audit/debug：图修订、求值事件、边 ID 和 Quest Pool transition 均可追溯，Windows 页面提供只读调试投影。
