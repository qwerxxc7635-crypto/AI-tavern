# Ember Tavern V0.3 Dynamic Locations

## 1. 目标与边界

动态地点让玩家在离开初始城市后仍能继续探索，同时避免在创建世界时生成完整地图。地点是 SQLite 中可查询、可恢复的世界事实图；AI 只为一次明确的扩展请求提出候选，不能直接移动玩家、改写已存在地点或批量铺开世界。

M6-T04 不实现格子地图、坐标、寻路、战棋、距离数值或地图页面，也不修改 Rules Engine、D20、Quest、NPC、Adventure、World Seed、Provider 或 portable archive 格式。M6-T05 才引入主动势力行为。

## 2. 地点合同与尺度

`DynamicLocationProfile` 支持 `REGION`、`COUNTRY`、`CITY`、`VILLAGE`、`DISTRICT`、`TAVERN`、`SHOP`、`RUIN`、`DUNGEON` 和 `SPECIAL`。每个地点具有稳定 ID、可选父地点、Constitution revision、事实 revision 和 generation provenance。

物化级别只有两种：

- `OUTLINE`：来自已确认 WorldBible 的既有名称、描述、层级和势力引用；没有伪造气氛、特征或当前局势。
- `DETAILED`：一次显式 Generator 请求产生并通过本地验证，必须包含气氛、特征和当前局势。

层级最大深度为八，父节点必须存在且属于同一 Campaign。自引用、环、缺失父节点、稳定 ID 重复及 Unicode/空白/大小写规范化后的重名都被拒绝。

## 3. 渐进物化

锁定 Constitution 时，migration 17 将既有 `world_bibles.locations_json` 原样投影为 `OUTLINE` 节点，并按父子关系建立初始连接。这个步骤不调用模型，也不增加地图内容。

后续只有两种显式扩展：

- `CHILDREN`：为当前地点具体化一至八个直接子地点；
- `CONNECTED`：在当前地点同一层级具体化一至八个相连地点，使玩家可以离开预设城市继续旅行。

统一任务 `GENERATE_LOCATIONS` 接收起点、模式、请求数量、最多 64 个既有地点摘要、允许的 Faction ID，以及锁定 Constitution 的 technology、magic、society、politics 精确证据。输出数量必须与请求完全一致；CONNECTED 候选必须连接起点，CHILDREN 候选必须以起点为父节点。任何越权 Faction、证据改写、未知连接、重复连接或完整地图式输出都会被拒绝。

Windows 服务复用既有 Generator Runner、Provider、Prompt、schema 和 generation audit；相同 Campaign、起点、模式及数量的同时请求在服务内合并。Native 在 `BEGIN IMMEDIATE` 事务中重新构造输入并复核 raw/validated output，再原子写入 generation record、地点与连接。idempotency key 仅能重放完全相同的输入、上下文、generation ID 和输出。

## 4. 移动与持久化

`campaign_location_states` 保存玩家当前地点和严格递增 revision。移动只能发生在父子节点或显式连接之间；不能原地移动、跨 Campaign、跳到未知/非相邻地点或使用过期 revision。

每次成功移动都会先追加 `location_travel_events`，再以 optimistic revision 更新当前位置，二者位于同一 immediate transaction。`operationId` 重放不重复增加 revision；同一 operation 的目标、模式或基线 revision 发生变化时 fail closed。关闭并重开数据库后，地点图、当前位置、revision 和旅行历史保持一致。

地点和连接是已经成立的世界事实，在 Campaign 存续期间不可静默删除或改写身份。portable `.emtavern` 对 schema 17 新表的正式携带及历史 fixture 升级继续由 M10-T05 集中处理。

## 5. UI 与后续边界

M6-T04 提供桌面服务能力，不新增地图页面，也不返工 M0 至 M4 已完成页面。后续自然展示地点时必须复用现有 Design Token、UI Primitive 与 Game Component，遵循《Ember Tavern 视觉风格手册 V1.0》，并把 AI 表现为世界/命运生成系统。Feature Page、Legacy UI Migration 和最终 Visual Consistency Audit 仍由 M10-T07 统一收敛。
