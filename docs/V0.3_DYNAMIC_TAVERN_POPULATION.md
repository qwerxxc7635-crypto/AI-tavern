# V0.3 Dynamic Tavern Population

## 1. 目标与权威边界

M7-T01 将酒馆人口从“初始化时生成的固定名单”扩展为可重复、可恢复的本地投影。投影读取当前 World、Location、Clock、ACTIVE Faction、最近 Event 和 NPC 互动历史；SQLite 中的身份、上下文、机会与历史是唯一真实来源，React 临时列表和模型输出都不能直接成为事实。

既有 Tavern owner、resident 和 visitor 继续作为 `OWNER` / `ESTABLISHED` 来源参与投影，不回滚或重做已完成的 Tavern Initialization。动态来源使用 `LOCATION`、`CLOCK`、`FACTION` 和 `EVENT`，并通过 `(tavern_id, source_kind, source_id)` 唯一映射到一个稳定 NPC LOD 身份。

## 2. Context 与投影规则

`TavernPopulationContext` 固定包含：

- World Bible `updated_at`；
- 当前 Dynamic Location ID 与 location revision；
- 全部 World Clock 的 current/max/updatedAt；
- ACTIVE Faction 的 revision、current action、player relation 与 territory；
- 最近八个 Game Event ID；
- 既有 NPC conversation 与已标记 important 的历史身份。

投影只选择当前上下文实际激活的来源：发生过移动后当前地点可带来旅人；已推进的 Clock 可带来关注者；控制当前位置的 ACTIVE Faction 可带来联络人；最新 Event 可带来见证者。来源首次出现时创建一个绑定锁定 Constitution 的 LOD0 身份；同一来源后续必须复用同一身份，替换或漂移会 fail closed。

上下文与机会均未变化时返回现有快照，不增加 revision、encounter count 或 cycle，也不调用 NPC Generator。时间、事件、地点或势力事实变化时只更新受影响来源；不再活跃的普通来源变为 `ABSENT`，important 或历史身份继续 `PRESENT`。

## 3. 机会投影

机会只从现有事实投影：

- `RUMOR`：当前有效 NPC 来源持有的 Rumor World Fact；
- `QUEST`：当前有效 NPC 发布的 AVAILABLE Quest；
- `FACTION`：当前位置相关 ACTIVE Faction 的 current action；
- `CLOCK`：已推进 Clock 的当前进度；
- `EVENT`：最新 Game Event。

机会不执行 Quest、Faction 或 Clock 后果，也不创建新的业务事实。仅有 owner 且没有机会时，状态显式保存 `emptyState=true`。

## 4. LOD 晋升与重要身份

玩家聚焦一个 `PRESENT` 的 LOD0 身份时，Windows 服务只调用既有 `NpcLodService.upgrade` 晋升该身份到 LOD1；不会批量生成全员。晋升成功后 Native focus 事务重新读取 canonical profile，验证 identity anchor、population role、profile revision 和 population revision，再把成员标记为 important 并追加 focus history。

important 是单向持久状态。后续上下文不再选择该来源时，身份仍保留并继续出现在人口历史中。既有完整 NPC 的 relationship、knowledge、memory 与 Quest 引用不被人口投影改写；动态身份的关系引用只能通过既有 LOD/知识边界在后续显式事务中增加，M7-T01 不编造关系。

## 5. SQLite 与事务

schema 19 新增：

- `tavern_population_states`：当前 canonical context、opportunities、revision 与 empty state；
- `tavern_population_members`：稳定来源映射、presence、important 与 encounter history；
- `tavern_population_cycles`：append-only 有效投影历史；
- `tavern_population_focus_events`：append-only 重要互动历史。

数据库触发器验证 Tavern/Campaign、NPC profile、既有 owner、Location、Clock、Faction 和 Event authority，禁止身份漂移、历史倒退和 Campaign 存续时删除。TypeScript Repository 与 Rust Native 都使用 `BEGIN IMMEDIATE` 原子提交 state、member 与 history；operation ID 支持一致重放并拒绝冲突复用。

关闭并重开本地 SQLite 后，来源身份、LOD profile、presence、important、encounter count、projection cycle 和 focus history 保持一致。portable `.emtavern` format v2 尚未包含 schema 19 新表，其正式跨版本导入导出和历史 fixture 升级仍属于 M10-T05。

## 6. 桌面接口与后续边界

Native 提供 `tavern_population_get`、`tavern_population_project` 和 `tavern_population_focus`。Windows `TavernPopulationService` 对同 Campaign 的并发 refresh 和同 NPC 的并发 focus 进行合并，并严格解析 Native 快照。

M7-T01 不新增多 NPC 对话 UI、不做 speaker arbitration、不锁定正式回复，也不重写既有 Tavern 页面。M7-T02 才消费 population snapshot 建立多 NPC Scene 与 UI。届时复用现有 Design Token、UI Primitive、`NpcCard` 及游戏组件，并遵循 [`EMBER_TAVERN_VISUAL_STYLE_GUIDE_V1.md`](EMBER_TAVERN_VISUAL_STYLE_GUIDE_V1.md)；完整 Legacy UI Migration 和 Visual Consistency Audit 仍由 M10-T07 统一完成。

## 7. 验证矩阵

- context：World/Location/Clock/Faction/Event/History canonical 投影；
- identity：同来源复用、来源替换拒绝、既有名单兼容；
- change：Clock/Event 变化只替换受影响来源；
- LOD：LOD0 聚焦只晋升一个身份，晋升前禁止 focus；
- persistence：revision、幂等、append-only history、关闭重开；
- state：owner-only empty state、important/history 保留；
- desktop：refresh/focus 并发合并、坏快照拒绝。
